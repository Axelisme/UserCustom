# Always-resident authority index

1. **Fixed subject:** Every review binds to one immutable fixed subject; a Git-backed subject is one exact clean commit and tree.
2. **Mutation authority:** Persistence mutation requires current user authority or an in-force task-scoped user grant naming the mutation and its conditions.
3. **Reorientation:** Load governing text just in time. After compaction or handoff, reread the task `INDEX.md` and the `SKILL.md` entry governing the next action when their original content is absent from active context. Read other skill sections, tickets, reviews, evidence, repository documents, and source files when the action that uses them starts, by anchor where one exists. A summary never replaces governing text or an authority grant. When the board cannot identify the next action, record the task's phase and whom it waits on in the tracker's Log instead of scanning all tickets, artifacts, or the task DAG to infer one.
4. **Test surface:** Tests validate only observable behavior and Interfaces; prose, document wording, static content, configuration values, and repository data remain outside the test surface.
5. **Subagent scheduling:** Launch subagents in the background and continue independent work rather than block-waiting or polling; each foreground wait keeps the turn open, blocks compaction, and can exhaust the context window.
6. **Tool turns:** When two or more tool calls are independent and no result is needed to formulate another, issue them in one parallel tool-call turn. Keep model-facing output bounded; write bulky output to an artifact and return its outcome, relevant excerpts, and path.
7. **Writing:** Write human-facing text plainly: mechanism, numbers, and conclusions in active voice, one idea per sentence, each sentence carrying a concrete fact or action. Open the `unslop` skill for the final pass on a long document a human will read.
