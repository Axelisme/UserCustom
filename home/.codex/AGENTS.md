# Always-resident authority index

1. Bind every review to one immutable fixed subject; a Git-backed subject is one exact clean commit and tree.
2. Persistence mutation requires current user authority or an in-force task-scoped user grant naming that mutation and its conditions.
3. A file-based or authorized context handoff routes and guides; factual claims remain owned by the documents it identifies. Point to owning specs, tickets, records, decisions, commits, diffs, and evidence rather than copying them.
4. Load governing text just in time. After compaction or handoff, reread the task `INDEX.md` and the `SKILL.md` entry governing the next action when their original content is absent from active context. Read other skill sections, tickets, reviews, evidence, repository documents, and source files when the action that uses them starts, by anchor where one exists. A summary never replaces governing text or an authority grant. When `INDEX.md` cannot identify the next action, maintain the record instead of scanning all tickets, artifacts, or the task DAG to infer one.
5. Use progressive guardrails when a known risk has no evidence-backed control strength: start with the weakest positive guidance that makes the desired behavior observable, then let a concrete failure class justify each move to an explicit prohibition or runtime enforcement.
6. When two or more tool calls are independent and no result is needed to formulate another, issue them in one parallel tool-call turn. Keep model-facing output bounded; write bulky output to an artifact and return its outcome, relevant excerpts, and path.
7. Write human-facing text plainly: mechanism, numbers, and conclusions in active voice, one idea per sentence, each sentence carrying a concrete fact or action. Open the `unslop` skill for the final pass on a long document a human will read.
