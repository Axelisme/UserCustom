# Record operations

## Document authority

Authority has two levels. Classify the fact being changed by where it lives, not by its wording.

| Level | Location | Change authority |
|---|---|---|
| **User decision** (用戶裁決) | `decisions/NNNN-slug.md` | Binding. Only the user supersedes it. |
| **Design reference** (設計參考) | `spec/`, ticket contracts, Plan | Derived from user decisions. The Orchestrator may redesign it after weighing implementation cost, and records the new design and its reason in the spec. |

Ask the user only when a change would contradict a user decision or redefine the Goal. Settle every
other gap yourself: design always misses details, and low-leverage questions cost the user more than
a recorded redesign. Moving a fact into `spec/` cannot lower the authority of a user decision.
Every decision file quotes the user; a design choice without a user quote belongs in `spec/`.

This classification decides whether the user must decide, not who may execute a change. Existing
mutation grants and role permissions still apply. A receiver returns changes outside its assignment
to the Orchestrator.

## Maintain the record

Records hold what an agent needs now or later and cannot recover from code, Git, or the collab tools.
The user rarely reads them. The Orchestrator owns task records except the exact role writes in
[Record permissions](lane-authority.md). Each fact has one owner; other records point to it.

| Fact | Owner |
|---|---|
| Requested outcome and active verbatim Standing orders | INDEX Goal and Standing orders |
| Ticket board | INDEX Tickets, generated by `plan.py locate` |
| Next action of each line of work in flight, and whom it waits on | Tracker Plan, one `Next: <action> — waiting on <who>` line each, pointing to the owning ticket, question, or decision |
| Task-created resources that outlive a lane | Tracker Resources |
| Design reference | `spec/`, entered through `spec/scope.md` |
| User decisions | `decisions/NNNN-slug.md`, routed by `decisions/README.md` |
| Ticket outcome, scope, dependencies, criteria, open user questions | Ticket contract sections |
| Status and branch | Ticket frontmatter |
| Execution milestones | Ticket Plan |
| Facts a later agent needs that code, Git, and decisions cannot supply | Ticket or tracker Notes |
| Gate results and range review verdicts | `runs/<short-sha>/` |
| Commits, diffs, execution history | Git |
| Assigned research deliverable | `research/`, cited by its ticket |
| Rerunnable task scripts | `scripts/`; output to stdout or `research/` |

**Rewrite, do not append.** Plan, Notes, Resources, `decisions/README.md`, and gate summaries are
snapshots. Each write replaces the whole section or file with the current state and drops what is no
longer true or useful. Only decision files accumulate.

Write Notes when a later agent would otherwise go wrong or redo work: a dead end, a non-obvious
reason, a constraint discovered during work. Resources lists what the task created that the collab
tools do not track and that outlives a lane: background processes and their ports, files outside the
task directory, external configuration, data written for the user. Each line names what, where, why
it is kept, and when to remove it.

INDEX Goal changes only when the user redefines the outcome. The tracker has no branch or collection;
it stays `doing` until the user completes or abandons the task.

Only the Orchestrator changes status. Frontmatter has `id`, `status`, `depends_on` (a flow list of
this task's IDs, or `[]`), and `branch` when a checkout exists.

| Status | Meaning |
|---|---|
| `todo` | Contract being settled |
| `ready` | Contract, seed, and gates prepared; not started |
| `doing` | Writer dispatched or Orchestrator implementing |
| `blocked` | Started work stopped by a decision, new dependency, or external condition |
| `closed` | Gates passed and the candidate, if any, collected |
| `dropped` | Abandoned, superseded, or split |

A ready ticket awaiting dependencies stays ready; the board marks `ready ▶` when they are closed.
External conditions belong in the contract with their blocker and owner, not in `depends_on`.
Update status and regenerate the board. On a size warning, rewrite Notes and Plan shorter, or shorten
INDEX Goal while keeping the orders and board whole.

## User decisions

Put a question's scenario, impact, options, and recommendation in the ticket's User decisions, or in
tracker Plan for task-level questions. Options too long for that section may sit in a `spec/` file
while the question is open.

Save the answer in the next numbered decision file (select the number from `ls`), first line
`Status: accepted`. The file holds the question as the user saw it, the full text of the adopted
option, and the user's answer verbatim in 「」, so a later redesign reads the user's own words rather
than a paraphrase. Each rejected option keeps one line with the reason. Then delete the options from
the ticket or spec and cite the decision file in their place. Rewrite `decisions/README.md`: it
lists in-force decisions by domain, one line per decision with its ID and title. A decision may
appear under several domains.

Mark a superseded decision `Status: superseded by <file>` and drop it from the routing list; the file
stays. Apply custody to quotations, ratification, and standing orders. Block only the started work
waiting on the answer.

## Close

Close a ticket when its gates pass on the collected candidate and the Orchestrator has checked the
criteria they establish. Criteria that need judgement are covered by Collab's
[range review](../../collab/references/review.md#range-review) before landing, not per ticket.
Set closed and refresh the board. Dropped work keeps its reason or replacement pointer in Notes.

## Archive

On the user's completion or abandonment, close or drop every non-tracker ticket and surface unresolved
items. Tracker Resources must be empty, or each remaining entry handed to the user. Set tracker closed
or dropped with the decision source, run `locate`, then `scripts/plan.py archive`. Archive keeps the
record intact. An enduring decision becomes a tracked ADR only on user request.
