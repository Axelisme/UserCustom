# Record operations

## Maintain the record

Records live under `.agent_state/plans/<task-id>/` in the main checkout while code worktrees remain
separate. The Orchestrator writes them unless a role's exact write below says otherwise.

Each fact has one **owner record**. Other records link to it.

| Fact | Owner record |
|---|---|
| Goal and verbatim Standing orders | INDEX, written by the Orchestrator |
| Ticket board | INDEX `## Tickets`, generated by `plan.py locate` |
| Task phase and whom the task waits on | The `tracker` ticket's Log |
| Approved scope and its boundaries | `spec/scope.md` (`Status: draft`, then `accepted`) |
| A user decision: the answer and its effect | `decisions/NNNN-slug.md`, one per decision |
| Contract, dependencies, acceptance, and open user questions | Ticket contract sections |
| Status, branch, milestones, and what happened | Ticket frontmatter, `## Plan`, and `## Log` |
| One review round's brief | `tickets/<id>/review-NN.md`, written by the Orchestrator |
| One review round's judgement | `tickets/<id>/review-NN.verdict.md`, written by the acceptor |
| Gate results for a clean commit | `runs/<short-sha>/`, written by whoever ran the gates |
| Commits, diffs, and progress between events | Git |
| Investigation output, inventories, caller surveys, design analysis | `research/`, or `spec/` when it freezes a contract; the ticket cites it |
| A proposal awaiting the user's answer | `spec/`, frozen once proposed |
| Task-owned scripts that can be rerun | `scripts/`; output goes to stdout or a `research/` path |
| Authority and its limits | The decision or grant that confers it, cited from `spec/scope.md` |

The ticket is a GitHub issue: the contract sections are its body, settled before `ready` and rarely
edited after; the Log is its comment thread. The INDEX board is the Kanban view over all tickets, and
INDEX is the task's README: its Goal is the outcome the user asked for in one or two sentences and
changes only when the user redefines it.

The **tracker** is the task's tracking issue. `create` adds it as `tickets/tracker`; it stays `doing`
until the user completes or abandons the task, has no branch, and is never reviewed or collected. Its
Log records the task's phase and whom it waits on, present state first because the board shows only
its last line (`planning: six tickets drafted, waiting on the user's choice of X`). A task waiting on
the user keeps the tracker `doing`. Name in that line the `todo` ticket whose contract is being
settled. An event a ticket owns goes in that ticket's Log.

**Status** is the Kanban column in ticket frontmatter. Only the Orchestrator changes it.

| Status | Meaning |
|---|---|
| `todo` | The contract is still being settled. |
| `ready` | Contract, seed, and gates are prepared; work has not started. A ready ticket waiting on dependencies stays `ready`; the board shows `ready ▶` once every dependency is `closed`. |
| `doing` | A writer is dispatched, or the Orchestrator is implementing. |
| `review` | A fixed candidate is waiting for, or under, acceptance. |
| `blocked` | Started work is stopped by a user decision, a dependency added mid-flight, or an external condition. |
| `closed` | Every criterion is accepted and the candidate, if any, is collected into integration. |
| `dropped` | Abandoned, superseded, or split. |

Frontmatter holds `id`, `status`, `depends_on` (a flow list of this task's ticket ids, `[]` when
none), and `branch` when a checkout exists. An external condition, such as another task's candidate,
lives in the contract and shows as `blocked` with its Log line.

**The Log** is append-only, newest last, and always the ticket's final section, because `locate`
shows its last line on the board. Write one line per event:

```
- MM-DD HH:MM → <status>: <reason or pointer>
- MM-DD HH:MM <event>: <pointer>
```

Append with `printf -- "- $(date '+%m-%d %H:%M') <event>\n" >> <ticket.md>`: one call, no prior read,
and the clock supplies the time.

Every status change gets a Log line; that pairing is the record's update rhythm. Other lines note a
dispatch (with the subagent id, so a successor can find it), a reconcile or collect (with the commit),
a verdict (`R02 BLOCKED`), a contract change (with its authority), or a user decision (with a pointer
to its `decisions/` file). Everything finer stays in Git and the run.

**The Plan** is an optional milestone checklist for a ticket built or reviewed in parts; tag each
milestone with the criteria it serves. The unchecked Acceptance boxes remain the work left.

When authority changes the contract after `ready`, amend the section in place, move the superseded
wording with its authority pointer to the ticket's `history.md`, and add a Log line. When
`size_warnings` names a ticket, move its oldest Log lines to `history.md`.

A user matter goes in the ticket's User decisions as the question: scenario, impact, options, and
recommendation. The answer is written once, verbatim, to `decisions/NNNN-slug.md` (the next number
from `ls`; first line `Status: accepted`, later `superseded by NNNN`); the ticket links it and logs
one line. A decision that has no ticket needs only its file. A superseded proposal carries
`Status: superseded by <file>` on its first line. A lapsed standing order moves intact from INDEX to
`decisions/NNNN-retire-<slug>.md` with its date and reason, quoting a revocation verbatim. While a
question blocks started work, the ticket is `blocked`; unrelated tickets continue.

When `size_warnings` names INDEX, shorten the Goal; the Standing orders and the board stay whole.

The update is complete when every changed fact sits once in its owner record and the board, after
`locate`, shows each ticket's true status and latest event.

## Review rounds

A round judges named acceptance criteria of one ticket on one fixed commit. Round numbers are two
digits and continue across the ticket's lifetime, including rounds that cover later milestones.

- `review-NN.md` is the acceptor's whole brief, created from `../templates/ticket/review.md` before
  dispatch and left unchanged afterwards: subject commit and tree, baseline, review checkout, the
  criteria judged, paths to the gate summaries, and, from round 2, every previous finding's
  disposition (fixed with its commit, declined with a reason, or moved to a user decision).
- `review-NN.verdict.md` is the acceptor's judgement, created from `../templates/ticket/verdict.md`
  at the absolute path the brief names. Its frontmatter `outcome` is `COMPLETED`, `BLOCKED`, or
  `UNREVIEWABLE`; finding IDs are `RNN-F<m>`.

A contract change during a round voids the round; the next brief states what changed. After the
verdict, the Orchestrator checks the boxes it establishes, sets the status, and adds the Log line; the
findings stay in the verdict file.

## Close

A ticket closes when every applicable criterion is checked through a COMPLETED round, or through the
Orchestrator's gate judgement for a gates-only ticket, on the collected candidate. Set
`status: closed` and end the Log with `→ closed: RNN COMPLETED, collected <commit>`.
Dropped work keeps its unchecked criteria and a Log line with the reason and any replacement ticket.
A replacement ticket may cite a criterion the original already passed as `accepted in <ticket> RNN`
and check it. Gate logs and summaries stay in `runs/` and archive with the task, like CI logs kept
with a PR; rounds and verdicts point to them rather than copy them.

Closure is complete when the board shows the ticket closed and its lane is retired or has an owner
and cleanup condition in the Log.

## Archive

Archive only when the user completes or abandons the task. First bring every ticket except the tracker
to `closed` or `dropped`, surface anything unresolved, and retire owned temporary resources. Then
close the tracker (`→ closed: user completed the task`, or `→ dropped: user abandoned the task`),
run `locate` so the board shows it, and run `scripts/plan.py archive`. A decision that must outlive
the task becomes a tracked ADR only on user request. Archive is complete when the whole record moved
intact and every retained execution resource has an owner and cleanup condition.
