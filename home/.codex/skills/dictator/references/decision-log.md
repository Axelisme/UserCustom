# 決策日誌範本

結案逐條報告是這份日誌的**投影**,不是重寫。記的時候就照報告要的形狀記,結案時才不必
憑記憶重建。

## 一則決策的四個欄位

- **採用** —— 實際做了什麼。寫得夠具體到能對回 diff。
- **替代** —— 認真考慮過、但沒選的方案。沒有真的考慮過就寫「無」,不要補一個假的。
- **理由** —— 為什麼是它。寫取捨,不要只寫優點。
- **可逆性** —— `可逆` 或 `鎖死`。這欄同時是 A/B 邊界的證據:凡是你判定「可逆、自己
  決定」的,結案時 user 要能指回這一行校正界線。判到 `鎖死` 就代表你當下應該停下問,
  日誌裡不該出現「鎖死但我自己決定了」的組合。

## 什麼該記

記**非顯而易見**的:換掉原訂做法、選了讀者會問「為什麼不用 X」的路、或你曾經猶豫過的。
不記例行施工——「新增 test」「跑 lint」「照現有 pattern 加一個 handler」不是決策。
判準:三個月後有人問「這裡當初為什麼這樣」,答得出來才值得記。

寧可漏記一則例行的,不要漏記一則你猶豫過的。

## 範例

以下是一個「把設定載入從 YAML 換成 TOML」任務跑完後的日誌。

---

# dictator-log: config-format-migration

進入時間: 2026-07-28 / 觸發語:「這個你全權決定」

## 決策

### 1. 用 adapter 層包住 parser,而不是全域換掉 `load_config()` 的簽章

- **採用**: 新增 `config/_parse.py`,`load_config()` 對外簽章不動,內部依副檔名分派。
- **替代**: 直接把 `load_config(path)` 改成 `load_config(path, fmt=...)`,由 21 個
  呼叫端各自傳格式。
- **理由**: 替代方案要動 21 個檔、且把格式知識洩漏給每個呼叫端;adapter 只動 2 個檔,
  格式知識收在一處。代價是多一層間接,`_parse.py` 目前只有兩個分支、看起來偏薄。
- **可逆性**: 可逆 —— 之後要攤平成顯式參數,是局部重構。

### 2. 保留 YAML 讀取路徑,不在這次移除

- **採用**: TOML 為預設,`.yaml` 仍可讀,不發 deprecation warning。
- **替代**: 一次砍掉 YAML。
- **理由**: repo 裡還有 3 份 fixture 是 YAML 且屬於別的 test suite,砍掉會讓那些 test
  紅在與本任務無關的地方。留著的代價是多一條要維護的路徑。
- **可逆性**: 可逆。

### 3. 用 stdlib `tomllib` 而不是 `tomlkit`

- **採用**: `tomllib`(唯讀,Python 3.11+)。
- **替代**: `tomlkit`(可保留註解地回寫)。
- **理由**: 目前全部用途都是唯讀載入,`tomlkit` 的回寫能力沒有使用者;少一個依賴。
- **可逆性**: 可逆 —— 真的要回寫再換,parse 呼叫點只有一個。

## 曾接近授權邊界但判定仍在授權內

### B1. 刪掉了 `configs/legacy/` 下的 4 個 `.yaml`

判定在授權內: 它們是 fixture(程式碼資產),不是 §B 講的「非程式資料」,且 git 有歷史。
若 user 認為 fixture 也算 data,請校正界線。

### A1. `_parse.py` 的分派要不要做成 plugin registry

判定**不是**重大分歧: 兩個方案都能在實作後靠局部重構切換,不鎖死,所以照 §A 口訣自己
拍板(選了 if/else,見決策 1)。
