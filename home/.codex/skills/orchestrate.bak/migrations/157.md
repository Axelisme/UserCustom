# Migrate to Orchestrate v157

## The gate script has a home and a guide

S2.5 required Root to prove each stop "in an isolated checkout at an exact bound SHA" and left the
rest to improvisation. Two increments lost a defect to that: a fully green test suite shipped a type
error because nobody remembered to run the type checker that day, twice, on different Slices.

`references/gate.md` is the guide for writing the script that check set lives in. It belongs at
`.agent_state/orchestrate/<task-id>/gate.sh`, per task, repo-local, and deliberately **not** tracked
by Git — it is agent scaffolding, not product, and the repository's own gitignored agent workspace
is where scaffolding belongs. Nothing in it travels with a clone; a fresh checkout has no gate until
one is written.

S2.5 now points at it and keeps only what is the standard's: the exit-code direction of each stop.
A TDD lane's Contract stop expects non-zero, the lane-ready stop expects zero, and a direct lane has
only the second.

## `lane check` reminds, and only reminds

When `.agent_state/orchestrate/<task-id>/gate.sh` exists, `lane check` adds one factual warning
naming it. The check still succeeds, collection is unaffected, and a repository with no gate script
sees nothing. This is the ninth-lane warning's shape, for the same reason: the package blocks on
what would corrupt the record — append-only, provenance, cleanliness, landing topology — and reports
on how thoroughly work was done. A missing gate run is the second kind.

The tool never runs the script. Orchestrate has exactly one subprocess entry point and it is
hardcoded to `git`; keeping it that way is worth more than mechanising a reminder.

## What the guide settles

Two questions came up while writing it, and the answers are in `gate.md` rather than here:

A gate is not the development loop. It runs twice per lane, not per save. The measured cost is 2.3
minutes for a 21-file affected suite against a lane that took over three hours.

Scope may vary; the person running it may not choose the variation. S4 refuses a result that changes
under a different selection of the same tree — which forbids a scope picked at run time, not a scope
derived from the tree. A selection computed from `git diff --name-only <base>...HEAD` yields the
same set for the same tree, so it adapts without breaking the binding. Its blind spot is recorded
too: one observed failure was cross-file test-state leakage in which neither file appeared in the
diff.

## Preserved mechanisms

No CLI grammar, ref, trailer, exit code, or lifecycle step changes. `lane check` gains a conditional
warning; `admission.md` gains a pointer; one reference document is added.
