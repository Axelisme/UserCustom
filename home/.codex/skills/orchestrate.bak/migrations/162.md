# Migrate to Orchestrate v162

## Silence has its own section, and its own reasoning

The five-minute quiet window and the `turnBudget` rule were fifty lines apart, each stated as a
caution. They are two halves of one mechanism, and `## Reading silence` now holds both.

The rule was written as a timing prohibition — "do not call `status`, resume again, or poll during
that window" — which describes the behaviour and hides the reason. The reason is that three states
produce identical silence from outside: a child still working, a child compacting, and a child
hard-cut by an exhausted turn budget. Only the third is over, and it is the only one
`pi-subagent-wake` will not report, because that extension excludes `turn-budget-exceeded`.

That is why the budget rule belongs here. Omitting `turnBudget` is what keeps the third row empty,
so silence has only its two harmless explanations and waiting is always right.

The instruction is now positive: **assume the child is alive.** The errors are not symmetric —
killing a compacting child discards the whole worker context and buys a fresh run in the lane, while
waiting on a child that is already gone costs the wait. This is not hypothetical; it is what
produced the rule, after a run was interrupted as dead while it was only compacting.

**The five minutes now carries its provenance: it is a felt bound, not a measurement**, chosen to sit
above an observed compaction rather than to match one. Pi exposes no compaction state and no child
heartbeat, so elapsed time is the only instrument available — the file now says so, because a reader
who cannot tell a missing signal from an unexamined one will eventually tighten the timer on the
argument that it feels long. The way to shorten it is to measure a compaction or to find a
distinguishing signal, and the timer retires the moment either exists.

## The binding stops restating what the profile enforces

An agent profile's frontmatter — `async`, `defaultContext`, `tools`, `inheritSkills`,
`systemPromptMode` — is configuration Pi enforces at dispatch. Prose repeating it is the second copy
that drifts, and the copy without teeth. The `Runtime dependency` list drops what the profile already
declares and keeps what it cannot: the semantics of `resume`, `interrupt`, `steer` and `stop`,
persisted sessions, status projection, and the public `observed` proof.

What the profile cannot declare is where it belongs in the admission sequence, so the binding now
says that and only that:

| stage | profile |
| --- | --- |
| S2 execution in a lane | `lane-worker`, or `mechanical-implementer` in a closed write scope |
| S2.8 Contract review | `contract-reviewer` |
| S4 Standards and Spec axes | `acceptance-reviewer`, one session per axis |

The roster was ahead of the binding. `contract-reviewer` matches S2.8's read-only pre-implementation
axis and has existed without the binding ever naming it, so a Pi Root reading this file alone would
not have known to dispatch it. `mechanical-implementer` declares no `async`, which the silence rules
now name explicitly: it returns inside the dispatching turn.

## The epoch seed says why it is hand-kept

The three orientation commands stay. They are a hand-kept list of the shape admission S4 refuses for
its own close-out checklist, and the reason they are right here is now written down: the arriving
reader knows nothing yet, so the seed cannot defer to an instrument it would first have to know
exists.

The unguarded cost is stated with it — a fourth orientation surface would be invisible, and the new
epoch would run three commands, get three answers, and believe it had finished — along with who
updates the block. The deeper fix belongs to `locate` and is recorded in the candidate backlog.

## One restatement v160 missed

Recovery described how a resume rebinds identity, which is dispatch.md's continuation rule in
different words. It now points instead. Pi's actual delta there is one sentence: resume preserves the
session and launch contract but returns a fresh run id.

## Correcting v160's migration guide

`migrations/160.md` claims, under "What this costs", that the inline seed is no longer inspectable
after the fact and that "there is no file left on disk to read — the evidence is the tool call."
**That is wrong, and it understated the change rather than overstating it.** `pi-handoff-context`
persists the inline handoff in the durable seed as well as the tool-call arguments, so it remains
part of the append-only session JSONL, integrity-bound by SHA-256 and byte length, after it stops
being projected into model context.

The inline seed is therefore *more* auditable than the `HANDOFF.md` it replaced, not less: the file
was overwritten between epochs and carried no integrity binding. v160 traded nothing away here.

`migrations/160.md` itself is unchanged. A migration guide is a receipt of what shipped under that
version, and a receipt that is edited later cannot be used to reconstruct what a reader was told.

## What this costs

`Reading silence` is longer than the two paragraphs it replaces. The added length is the reasoning
and the provenance, which is what lets a later reader change the number correctly instead of
guessing at it — but it is length, and this file is read whole by every Pi Root.

## Preserved mechanisms

Text only. No CLI grammar, payload key, ref, trailer, exit code, or lifecycle step changes. The
five-minute window, the `turnBudget` and `toolBudget` rules, the seed's three commands, and the
`observed` evidence requirement all keep their current behaviour; what changed is where they sit and
what they say about themselves. Codex and Claude bindings are untouched.
