# Migrate to Orchestrate v168

## Purpose

Cut the context a lane worker spends before its first production edit, by making the dispatch carry
the commit line it needs and by holding the admission to one conditional pointer per supporting
artifact. No lifecycle, authority, gate, validation mode, or completion criterion changes.

## Observable changes

- `references/dispatch.md` gains a **Commit command** section: Root fills the values in and the
  dispatch carries `lane commit --task-id <task> --lane-id <lane> --message-file <file>` whole. The
  flag semantics, the `Immutable:` read off the staged diff, and the `Origin: contract` pairing move
  here as their single source of truth. The dispatch inventory now names the command line where it
  previously named the orchestrate script path.
- The three lane-worker profiles keep *when* to pass `--contract` and `--amend-frozen` and drop the
  restatement of what those flags write; they point at the dispatch contract instead. A worker was
  measured reading the script and the whole package to rebuild a line it had already been given —
  after its production edits were written.
- `references/admission.md` S1 gains **Citing evidence in the admission**: carry the conclusion, and
  print a supporting path only with the condition that reaches it. A list of paths reads as an
  instruction to open all of them, and did — one lane opened four axis reports, the frozen spec, the
  ticket and the record index, 70KB, before its first edit.
- The lane-worker profiles' `grove` sentence becomes a positive default: reach for it *before*
  opening any source file, because the Contract names its symbols and grove goes from a name to that
  symbol's body without reading the file.
- No profile skills declaration, model, or runtime field changes.

## Active-task impact

None. Existing task refs, lanes, worktrees, trailers, acceptance state, and records remain valid. A
dispatch already sent under v167 stays executable: it names the script path, which still works.

## Manual steps

None required. Root composes the filled-in commit line from values `lane check` already reports, so
nothing new must be looked up. An admission written under v167 that lists supporting paths is not
invalid; the rule governs the next one written.

## Verification

Run `orchestrate.py doctor` and the repository test suite. Compare the v167 and v168 lane-worker
prompts to confirm the commit-mechanics paragraph and the `grove` sentence are the only body
changes, and that the `--contract` / `--amend-frozen` decision survives in the profile.

## Rollback

Restore the v167 documents and manifest together. Do not pair a v167 manifest with v168 documents.
