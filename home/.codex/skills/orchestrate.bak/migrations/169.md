# Migrate to Orchestrate v169

## Purpose

Give the acceptance re-review continuity rule a cheap discharge condition. The rule asked Root to
resume each *trusted* axis reviewer session; trust had no instrument behind it, so establishing it
became an unbounded search of the session store. No lifecycle, authority, gate, validation mode, or
completion criterion changes.

## Observable changes

- `runtime-pi.md` re-review continuity: one `subagent` fleet query settles each axis. A session the
  fleet still lists resumes; every other answer, an empty fleet included, starts a fresh reviewer.
  The criterion is no longer whether a session's context is *trusted* — a judgment Root could only
  reach by reading the session — but whether the fleet lists it, which is one call.
- The fallback now names what it carries: the prior **axis report from disk**, which is the durable
  form of the prior verdict. It previously said "the prior terminal report" without saying where
  that lives, which left recovering the reviewer's *context* looking like part of the obligation.
- A prohibition is added: never reconstruct a reviewer's context from the session store. A measured
  re-review read `No active subagent fleet` and then spent 156KB parsing the previous day's session
  JSONL — a third of that increment's entire Root tool-result payload — to recover conclusions that
  were already on disk in the axis report whose filename the search was keyed on.

## Active-task impact

None. Existing task refs, lanes, worktrees, trailers, acceptance state, and records remain valid. A
re-review already in flight under v168 may finish as dispatched; the rule governs the next one.

## Manual steps

None required. The fleet query is a call Root already makes, and axis reports are already written to
the plan directory's artifacts by the report rules in `references/admission.md`.

## Verification

Run `orchestrate.py doctor` and the repository test suite. Confirm `runtime-pi.md` no longer makes
resumption conditional on a session's trustworthiness, and that the acceptance re-review section
names the axis report on disk as what a fresh reviewer receives.

## Rollback

Restore the v168 documents and manifest together. Do not pair a v168 manifest with v169 documents.
