# Migrate to Orchestrate v171

## Purpose

Complete addressed reading by making task status name the exact lifecycle and admission sections a
reader needs, and make worker dispatches point at their admitted obligations instead of restating
them.

## Observable changes

- `status --task-id <task>` adds `step` only for uncollected work, pending collection, inventory
  warnings, or an accepted ref that is not landed.
- `status --task-id <task> --step` requests the state-derived pointer explicitly. The field contains
  only `n` and `open`; every `open` value is an exact address resolvable by v170 `show`.
- Uncollected work points to collection and S2.5, pending work to acceptance and S4, and
  accepted-but-unlanded state to landing and S5. Inventory warnings add the lifecycle Exceptions
  address.
- Clean self-placing status output remains unchanged when `--step` is absent.
- The dispatch contract now carries Binding, admission section addresses, the verbatim commit line
  and the call's volatile Delta. The admission remains the single obligation authority.

## Active-task impact

Existing refs, lanes, worktrees, trailers, acceptance state and records remain valid. A Root may use
`--step` on any active task immediately. Existing worker sessions may finish under their frozen
dispatch; the pointer-only convention governs the next dispatch or continuation.

## Manual steps

None. Status derives the pointer from current Git state and reads no new state file.

## Verification

Run `orchestrate.py doctor` and the canonical test suite. Confirm a clean task omits `step`, each
ratified trigger emits it, `--step` requests it explicitly, and every emitted address exits 0 through
`orchestrate.py show`.

## Rollback

Restore the v170 documents and manifest together. Do not pair a v170 manifest with v171 package
bytes.
