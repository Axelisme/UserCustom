# Migrate to Orchestrate v172

## Purpose

Make gate guidance produce checks that are meaningful on the lane's base and evidence that survives
lane teardown, and retire the acceptance receipt whose contents already have authoritative homes.

## Observable changes

- A check enters a gate only after its exact command has been observed green on the base tree; the
  recommended lane-ready shape is a menu to verify rather than a list to copy.
- Gate logs use a durable directory outside lane worktrees and managed task paths, while runner
  basetemps stay disposable inside the lane workspace.
- Machine-rework counts and diagnosis remain in the Slice ticket's `Current`.
- Standards and Spec axis reports retain their own counts and findings; the Slice ticket records the
  verdict and binds both report paths. No separate acceptance receipt is required.
- S4 moves frozen state named by `refresh` directly to the artifact of the gate that produced it.

## Active-task impact

Existing gate scripts remain valid, but their owners should verify every selected command against the
recorded base and move `LOG_DIR` before the next run if lane or integration teardown can remove it.
Existing axis reports and Slice ticket state remain valid; no receipt migration is required.

## Manual steps

For an active task, set its gate log directory to a durable repository-local path outside
`.agent_state/orchestrate/<task-id>/` and every lane worktree. Keep test basetemps in a lane-specific
runner directory.

## Verification

Run `orchestrate.py doctor` and the canonical test suite. Inspect the shipped v172 `gate.md` and
`admission.md` sections through `orchestrate.py show` and confirm the package manifest binds them.

## Rollback

Restore the v171 documents and manifest together. Do not pair a v171 manifest with v172 package
bytes or keep v172 receipt destinations while restoring the retired receipt mandate.
