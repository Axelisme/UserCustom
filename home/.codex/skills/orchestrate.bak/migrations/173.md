# Migrate to Orchestrate v173

## Purpose

Make command-bound refusals carry the corrective action their process already knows, so an agent can
respond without leaving the failed command to reconstruct state or consult prose.

## Observable changes

- Refusal envelopes may carry a non-empty `repair` beside `code` and `message`; lane-check
  diagnostics use the same three-field shape.
- A missing-lane diagnostic lists the task's live lane ids instead of discarding that projection.
- Identifier repair lowercases a rejected value when the lowercase form is valid.
- TDD mode mismatch explains that the check counts only uncollected Contract commits.
- Repairs state only behavior bound by the executing command and contain no shipped-document path or
  anchor.

## Active-task impact

Consumers that compare refusal or diagnostic keys by exact equality must admit `repair`. Success
payloads and exit status semantics are unchanged. No task, lane, acceptance, or landing state needs
migration.

## Manual steps

None.

## Verification

Run `orchestrate.py doctor` and the canonical test suite. Provoke a missing lane check and an invalid
uppercase ticket id; confirm each refusal includes a non-empty repair computed from live or rejected
values.

## Rollback

Restore the v172 package and manifest together. Consumers updated to read `repair` remain compatible
with v172 if they treat the field as absent there.
