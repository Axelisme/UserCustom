# Migrate to Orchestrate v177

## Purpose

Keep `status.collect_rounds` Git-derived when a lane carries an uncollected Contract amendment
alongside production already present in integration.

## Observable changes

- `status --task-id <task>` keeps the existing `collect_rounds` field and ticket mapping. A sync
  merge whose second parent is already in collected integration history is classified from its
  residual tree delta relative to that parent.
- A residual delta proven by the lane's accumulated `Immutable:` declarations is Contract-only
  carriage and does not create a production round. Any residual path outside those declarations
  remains production-bearing and counts.
- Ordinary production, pure Contract-amendment, own-lane sync, and two-lane no-local-change
  behavior remain unchanged.

## Report-version decision

`report_version` remains 2. This release changes only the Git-derived collect-round boundary; it
introduces no report schema or telemetry migration.

## Active-task impact

No report consumer migration is required. Continue reading `status.collect_rounds` for measured
production-bearing rounds and `lane check` for lane Git facts.

## Manual steps

None.

## Verification

Run the composed collect-round Contract test, the machine-facts Contract tests, the canonical test
suite, `orchestrate.py doctor`, and `orchestrate.py doctor diff 176 177`.

## Rollback

Restore the v176 package and manifest together. The v176 report schema remains compatible; only the
v177 composed Contract-amendment/sync boundary is reverted.
