# Migrate to Orchestrate v178

## Purpose

Move the shipped Pi runtime binding from the retired Root Context Epoch handoff flow to ACP
context management while preserving Pi Subagents dispatch, recovery, silence, authority, and
terminal safety.

## Observable changes

- Pi settings select `npm:billion-context-pi@0.1.24` and remove `pi-handoff-context`.
- Global ACP configuration disables `delegate` and `autoUpdate`.
- Every shipped Pi profile exposes `compress`, `decompress`, `search_context`, and `acp_status`
  without changing existing tools or read-only checkout restrictions.
- The Pi runtime binding describes ACP context management and removes the explicit handoff flow.
- Detached async runs require public process-terminal state `observed`.
- Workflow runs require public workflow `complete`, target child `completed`, and child `exitCode`
  zero.
- Both modes require Git identity, clean state, and gate evidence; timestamps, result files, and
  PID disappearance alone are not proof.

## Report-version decision

`report_version` remains 2. This release changes the Pi context-management and terminal-evidence
binding only; it introduces no report schema or telemetry migration.

## Active-task impact

No task record migration is required. Existing Pi Subagents dispatch, recovery, silence, authority,
and cleanup rules remain in force.

## Manual steps

None. Installation, setup, pinning, reload, and live HOME mutation remain user-owned and are not
part of this migration.

## Verification

Run the tracked Pi configuration Contract tests, orchestrate package integrity tests, release tests,
`orchestrate.py doctor`, and `orchestrate.py doctor diff 177 178 --runtime pi`. Do not run installation
or model-backed tests as part of this migration.

## Rollback

Restore the v177 package and manifest together. The v177 package remains compatible with the
existing report schema; only the Pi ACP composition, runtime binding, and terminal-evidence guidance
are reverted.
