# Migrate to Orchestrate v132

## From

v131

## Observable changes

The lane-worker model uses one worker per lane. Existing runtime items are redispatch targets for a lane-worker, Root performs pre-collect test review, and every worker performs cwd attestation.

## Active-task impact

No automatic conversion is performed. An already-running worker is not retyped or interrupted; Root manually coordinates whether to finish it or redispatch the remaining work.

## Manual steps

1. Assign one lane-worker to each lane.
2. Redispatch existing runtime items to a lane-worker when further work is required.
3. Require canonical cwd attestation before lane writes.
4. Perform Root's pre-collect test review before collecting the exact clean lane SHA.

## Verification

Confirm each lane has one worker, the dispatch records its canonical cwd, and pre-collect evidence includes the Contract-first test review.

## Rollback

Stop before `pin set`; keep existing refs, worktrees and runtime evidence intact, and resume only from an explicitly selected clean SHA.
