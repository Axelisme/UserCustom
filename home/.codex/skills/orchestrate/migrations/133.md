# Migrate to Orchestrate v133

## From

v132

## Observable changes

The Pi Adapter is mandatory for Pi dispatch. Acceptance requires exact run/process terminal evidence, while Root authority is unchanged.

## Active-task impact

No automatic conversion is performed. Existing active tasks and evidence remain untouched; only subsequent Pi dispatches use the Adapter lifecycle.

## Manual steps

1. Confirm the installed Pi Adapter is present and matches the release manifest.
2. Dispatch Pi lane work through the Adapter.
3. Retain exact run/process terminal evidence for the dispatched lane.
4. Keep all collect, candidate, landing and recovery decisions with Root.

## Verification

Run the release doctor and one isolated Adapter dispatch/attestation flow, then inspect the exact run ID and process-terminal evidence.

## Rollback

Stop before `pin set`; do not rewrite receipts or task state. Return to the last verified installed release through its normal setup path.
