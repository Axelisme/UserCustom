# Migrate to Orchestrate v135

## From

v134

## Observable changes

v135 is a docs-only release. Pi runtime guidance now says that long interactive background work should normally return control, or report progress and use `yield_goal` in goal mode, instead of holding the parent turn by default. It documents the bounded same-turn completion exception, prohibits sleep and polling loops, and separates progress reports from terminal, readiness, and collect evidence. There are no public behavior or Adapter changes.

The planning-with-files to dev-flow cutover is not implemented in v135. It remains a future atomic Wave B cutover with a separately authorized manual legacy migration.

## Active-task impact

No automatic conversion, cleanup, interruption, or state mutation occurs. Existing branches, refs, worktrees, candidate state, receipts, planning-with-files authority, and legacy tasks remain unchanged. Active Pi runs continue under their existing frozen Contract and exact-run evidence rules.

## Manual steps

1. Read and apply each guide from the repo's pinned version plus one through v135.
2. Reread `runtime-pi.md` and adopt its return, progress, `yield_goal`, wake-up, and bounded-wait guidance for future interactions.
3. Verify installed documents, profiles, and mandatory runtime assets with `doctor`.
4. Do not migrate planning files or legacy tasks; wait for the future atomic Wave B cutover and its separately authorized manual legacy migration.
5. After manual coordination and separate authority, run `pin set --root <repo>`.
