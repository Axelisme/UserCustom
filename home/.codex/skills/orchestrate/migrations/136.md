## Observable changes

v136 completes the atomic durable-task authority cutover: dev-flow is the sole active durable-task authority, and Wayfinder, to-spec, to-tickets, prototype work, and candidate-backlog lifecycle guidance share its generic task record. The shared admission standard now owns S0–S5, including minimum-complete design, without a second workflow state model.

Normal setup uses explicit active and retired lifecycle inventories. Retired-path ownership is classified before any HOME mutation, active identities and both logical releases are verified, and replacement verification succeeds before managed planning links are removed. The planning-with-files document is a one-release retired transition capsule for direct legacy diagnostics only; its script and templates retain their v135 bytes.

## Active-task impact

v136 migrates no legacy records. Existing legacy task directories remain byte-preserved; the dev-flow kernel may identify them and move a confined directory by symmetric archive/resume only. Existing Git branches, refs, worktrees, candidate state, receipts, and task evidence are not rewritten by release adoption.

Unfinished implementation and validation remain ordinary generic tickets. The candidate Git ref remains exact readiness authority, and current user authority is still required separately at every persistence or runtime mutation gate.

## Manual steps

1. Read and apply each guide from the repo's pinned version plus one through v136.
2. Accept and land only the complete exact B1+B2 candidate; if landing fails, stop before setup.
3. With separate current setup authority, run the normal no-argument `setup_config.sh`. It performs retired ownership preflight, installs and verifies dev-flow, then removes exact managed planning links. A foreign retired destination refuses before mutation.
4. If retired removal is incomplete, use the reported exact removed and remaining paths. The verified replacement stays usable, and normal setup rerun is the only removal recovery.
5. After setup succeeds, separately reload Pi and run installed Codex/Pi doctors, source/installed manifest parity, disposable new-record `create` plus `check`, and confined legacy archive/resume diagnostics.
6. Only after every installed check passes and with separate pin authority, run `pin set --root <repo>`. Until then the v135 pin remains unchanged.
7. Task archive and Orchestrate cleanup each require fresh current authority. Never infer either permission from landing, setup, reload, verification, or pin adoption.

## Rollback

Stop before each next gate when verification fails. Before setup, reject the candidate and correct it through the normal reviewed source path. After setup, do not recreate a retired installed authority or change the pin; keep the verified v136 replacement, leave the v135 pin unchanged, and repair forward. A setup removal failure is handled only by its exact report and normal setup rerun. A reload or installed-E2E failure is repaired forward before pin, archive, or cleanup.
