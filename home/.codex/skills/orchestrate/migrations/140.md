# Migrate to Orchestrate v140

## From

v139

## Observable changes

v140 makes `release` publishable again. Through v139 the command was gated on the current package
still matching its own manifest hashes, which no real release can satisfy: publication edits the
documents that manifest hashes, and the required exact-next migration guide is itself an unexpected
document at the current version. Both directions refused, so `release` could never succeed from the
command line.

Publication is now gated on package integrity instead of package immutability. The current manifest
must load and every document it lists must still exist; hash equality is no longer required.
`release` still refuses any target other than the exact next version, still requires the exact-next
migration guide, still verifies the published result against the target manifest, and still restores
prior bytes when that verification fails. Every other mutation command keeps the strict
hash-equality gate unchanged.

The source package drops the duplicated per-logical manifest corruption cases from its setup and
publication contracts. Codex and Pi manifests are still required to be byte-identical, so corrupting
each copy in turn tested one fact twice and blocked publishing the Pi manifest as a symlink.

## Active-task impact

None. No command that touches repository state, task worktrees, refs, acceptance, landing, or
telemetry changed. Task records, pins, and reports are unaffected, and no conversion is performed.

## Manual steps

1. Read this guide together with the shared admission standard.
2. Confirm the v140 source and installed package hashes before changing the installed runtime.
3. After package checks pass, use separately authorized `pin set` from the repository cwd. The pin
   records adoption; it does not install or select code.

## Verification

Run source and installed `doctor`; the package projection must be exactly 24 documents, 31
profiles, and 0 runtime assets. Run `doctor diff 139 140` once without a runtime filter and once for
each `codex`, `claude`, and `pi` filter. Confirm the Codex and Pi v140 manifests are byte-identical,
and that v130–v139 manifests plus v131–v139 migration-guide hashes are unchanged. Confirm v133–v139
manifests still load; v130–v132 predate `runtime_assets` and remain rejected by the structural
validator, exactly as under v138 and v139.

Publish the next disposable release from an edited, unsealed package copy and confirm it succeeds;
this is the behavior v139 could not perform. Confirm `release` still refuses when the current
manifest is absent, when a document it lists is missing, and when the target is not the exact next
version. Run canonical test discovery with zero failures and zero errors, then the release,
lifecycle, module, setup, lint, type, compile, and shell-syntax gates.

## Rollback

If any verification fails, stop before the next authority boundary. Before setup, reject the source
and repair it through the normal admitted lane. After setup, repair forward to a verified v140
package while preserving user data. Do not restore the v139 gate by hand, reseal a historical
manifest to make a package look healthy, or rewrite a pin.
