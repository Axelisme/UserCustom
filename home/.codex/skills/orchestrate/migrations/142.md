# Migrate to Orchestrate v142

## From

v141

## Observable changes

The release manifest stops binding shipped profiles that orchestrate does not dispatch. Through
v141 `profile_paths` bound every profile name in the fleet across all three runtimes, so editing an
unrelated profile invalidated the orchestrate package and forced a release that had nothing to do
with orchestrate. v141 itself was such a release: removing three planner and investigator profiles
changed nothing orchestrate does, yet required publishing a new package.

`PROFILE_NAMES` is now exactly `acceptance-reviewer` and `lane-worker` — the profiles orchestrate's
own SKILL and runtime documents name. The manifest binds 7 profile entries instead of 22: those two
names across `.codex/agents`, `.claude/agents`, and `.pi/agent/agents`, plus
`.pi/agent/APPEND_SYSTEM.md`, which stays bound because the runtime documents depend on the standing
orders it carries.

Nothing else changed. `doctor`, `doctor diff`, `pin`, and `release` keep their Interfaces, their
exit-code contract, and their atomicity guarantees. Drift in an unbound profile is no longer a
package-integrity failure; it is simply outside this package's scope.

## Active-task impact

None. No command that touches repository state, task worktrees, refs, acceptance, landing, or
telemetry changed. Task records, pins, and reports are unaffected, and no conversion is performed.

## Manual steps

1. Read this guide together with the shared admission standard.
2. Confirm the v142 source and installed package hashes before changing the installed runtime.
3. Port `manifests/142.json` to every fleet that keeps its own `manifests/` directory: `.pi` needs a
   relative symlink back to the Codex copy, `.claude` a hard link. `release` writes the manifest
   only into the skill directory it published from, and refuses to write through a link at all, so
   this step cannot be folded into publication.
4. After package checks pass, use separately authorized `pin set` from the repository cwd.

## Verification

Run source and installed `doctor`; the package projection must be exactly 26 documents, 7 profiles,
and 0 runtime assets. Run `doctor diff 141 142` and confirm the only profile differences are the
now-unbound entries. Confirm `verify_release` succeeds for the Codex, Claude, and Pi skill
directories. Edit a profile that is no longer bound, rerun `doctor`, and confirm it still passes —
that is the behavior this release exists to provide. Run canonical test discovery with zero
failures and zero errors.

## Rollback

If any verification fails, stop before the next authority boundary. Before setup, reject the source
and repair it through the normal admitted lane. After setup, repair forward to a verified v142
package while preserving user data. Do not widen `PROFILE_NAMES` by hand to make a stale manifest
verify, and do not reseal a historical manifest.
