# Migrate to Orchestrate v143

## From

v142

## Observable changes

No command, Interface, exit code, or Git operation changed. This release is entirely documentation:
the package's document set is restructured and two gaps in the Pi binding are closed.

**The runtime bindings now share one dispatch contract.** v138 decided that shared binding text keeps
only the runtime-neutral continuation invariant while mechanism names live in each runtime's delta,
but the decision was never carried out — `runtime-claude.md` and `runtime-codex.md` remained 28
near-identical lines, and the authority paragraph was repeated almost verbatim across three files
and `SKILL.md`. The new `references/dispatch.md` owns the pre-dispatch checks, the dispatch payload, the
cwd contract, the acceptance sequence, the continuation invariant, the terminal handoff, and Root's
authority. Each binding keeps only its own mechanism: `runtime-claude.md` and `runtime-codex.md` drop
to 10 lines, `runtime-pi.md` keeps every Pi-specific rule it already had.

**Package administration moved to `references/package-admin.md`.** `doctor`, `doctor diff`, `pin`, `release`, and
the ordered migration-guide rule are unchanged in substance; only a release ever reaches them, so
`SKILL.md` keeps a pointer. The uniform JSON receipt and exit-code contract stay in `SKILL.md`
because every command shares them.

**`SKILL.md`'s lifecycle is now a numbered sequence** with a completion condition per step, and the
non-linear operations (`lane drop`, `integration reconcile`, `--abandon`) follow it as exceptions
rather than interrupting it.

**Two Pi facts the binding never stated.** `status` reports `turnBudgetExceeded`, which is the only
way to tell a budget stop from any other stop. And a continuation does not inherit its budget: the
recovery descriptor restores `toolBudget` but not the initial turn budget, so a `resume` that omits
`turnBudget` runs unbounded.

**A closed enumeration of what Root may do when a budget stops a lane.** Root still chooses; the
binding only makes the options visible, including the one it never named — dispatching a new run into
the same lane. Changing the run is not changing the lane, so raising a budget costs neither the
Contract commits already made nor a fresh admission. Only a recut changes the Contract, and only a
recut needs re-admission.

**The dispatch payload carries the task record's `Envelope` and `Standing orders`** when the task has
a durable record, so a worker can honour a boundary the user froze and an instruction the user issued.

The shared admission standard is now reachable by path from `SKILL.md` instead of being named without
one. It continues to live in `dev-flow/references/`, which is not version-bound; that drift risk is
accepted rather than mechanised.

## Active-task impact

None. No command that touches repository state, task worktrees, refs, acceptance, landing, or
telemetry changed. Task records, pins, and reports are unaffected, and no conversion is performed. An
in-flight task may adopt this package between lanes without reworking anything already collected.

## Manual steps

1. Read this guide together with the shared admission standard, whose S0 was reorganised into a named
   four-stage sequence in the same change set.
2. Confirm the v143 source and installed package hashes before changing the installed runtime.
3. Extend the Pi overlay, which mirrors the Codex skill through relative links rather than copies:
   add `references -> ../../../../.codex/skills/orchestrate/references` beside the existing
   `migrations` and `scripts` directory links, and one per-file link for `manifests/143.json`. The
   Claude overlay symlinks the whole skill directory and needs nothing. `release` writes the manifest
   only into the skill directory it published from and refuses to write through a link, so this step
   cannot be folded into publication.
4. After package checks pass, use separately authorized `pin set` from the repository cwd.

## Verification

Run source and installed `doctor`; the package projection must list every document including the new
`references/dispatch.md` and `references/package-admin.md`, with 0 runtime assets. Run `doctor diff 142 143` and confirm the
differences are exactly the two added documents plus the changed hashes for `SKILL.md` and the three
runtime bindings. Confirm `verify_release` succeeds for the Codex, Claude, and Pi skill directories.
Confirm `../dev-flow/references/admission-standard.md` resolves from the installed `.codex`,
`.claude`, and `.pi` skill directories. Run canonical test discovery with zero failures and zero
errors.

## Rollback

If any verification fails, stop before the next authority boundary. Before setup, reject the source
and repair it through the normal admitted lane. After setup, repair forward to a verified v143
package while preserving user data. Do not hand-edit a manifest to make a stale package verify, and
do not reseal a historical manifest.
