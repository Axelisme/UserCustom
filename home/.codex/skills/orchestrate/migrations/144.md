# Migration 143 → 144

v144 answers a field report from a five-day, twelve-compaction migration. Nothing in it is a new
gate. Every change either moves a rule that was being ignored into a script that cannot be ignored,
or corrects a document that was wrong.

## Breaking: `lane create` requires `--group`

```
orchestrate lane create --task-id <task> --lane-id <lane> --group <need>
```

Existing scripts and dispatch prompts that call `lane create` must be updated; the command fails
with `cli_usage` otherwise.

`--group` names the need the lane serves. Reuse it when re-cutting or re-admitting the same need;
give a genuinely new need a new group. When in doubt, repeating the lane id reproduces v143
behaviour exactly, because each lane then stands alone.

**Why an argument rather than a convention.** The observed task spent about twelve lanes on one
ticket — `b51b-host-root`, `host-root-02`, `r3`, `r3-readmit`, `r4-token-replacement`,
`r5b-proof-capture` and so on. No rule was ever violated: `Machine rework: N/2` lives on the active
Slice ticket, and the prescribed escape at the cap is a recut, which creates a new ticket carrying a
fresh counter. The one instrument that could have seen the pattern was reset by the very move that
produced it. Grouping by a lane-id prefix was tried first and measured against those ids: it split
the one need into eight groups, the largest holding three, so the threshold could never fire.

## `lane_consumption`

`status` reports, per group, how many lanes the need has consumed and which ones — read from
append-only telemetry, so a collected, dropped, or abandoned lane still counts and a recut cannot
clear it. `lane create` emits a warning at six.

Membership is reported alongside the count deliberately: a count whose grouping is wrong is a
confident wrong number, which is worse than no number.

Six is not a budget. `admission-standard.md` S3 states what it means and the two acts that answer
it — merge the Slice with its neighbour, or rebind its oracle to the production entrypoint. Neither
stops to ask the user; a task can run unattended and still be redirected.

Lanes recorded before v144 have no group. Each stands alone rather than being folded into a guess.

## Pi binding corrections

Two statements in `runtime-pi.md` were wrong.

- **Resume does not keep the run id.** `resumeAsyncRun` mints a fresh id on every revival
  (`randomUUID().slice(0, 8)`); the session and launch contract survive, the id does not. Root must
  use the id `resume` returns — the old one inspects a dead run.
- **A turn budget is a soft ceiling, and the worker is warned once.** `maxTurns` plus `graceTurns`
  (default 1), after which the supervisor aborts with partial output. The budget is stated in the
  worker's system prompt at launch, and process-mode execution has no live steering, so nothing
  reminds it as the ceiling approaches.

The binding now also states that it deliberately overrides upstream on `turnBudget` while adopting
upstream's warning about `toolBudget` — the two are different kinds of limit, and upstream's single
sentence conflates them. `toolBudget` degrades: exhausting it blocks read tools and leaves mutation
tools, producing a worker that can write but cannot see.

`lane-worker` now carries the reason for its commit cadence rather than the bare instruction.

## dev-flow (unversioned, same subject)

- `SKILL.md` split its ten laws by how each one actually fails. Four were one idea stated four
  times and now sit under **jurisdiction**; three more under **custody**. Two remain prohibitions,
  because they were violated in the field despite existing — the second-ticket-store law now names
  the specific workaround it refuses.
- `scripts/plan.py` reached `record_version 3` and validates: ticket status is `open | active |
  closed` with a separate disposition on `closed`, and `refresh` reports a record whose `INDEX.md`
  predates its tickets. Records at version 2 are grandfathered untouched.
- `admission-standard.md` S1.1 now requires the Slice to say how its oracle reaches the named
  production entrypoint, S3 gained the lane-consumption rule above, and S5 gained the per-accept
  record update.
- `dev-flow` and the admission standard carry hand-maintained version numbers. They have no doctor
  and no manifest; a report needing certainty still cites the Git subject.

## Installation

No new files outside `.codex`. The Pi overlay needs a `manifests/144.json` link alongside its
existing per-file links; Claude symlinks the whole skill directory and needs nothing. Run
`setup_config.sh` from the primary checkout, then `pin set 144`.
