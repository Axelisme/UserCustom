# Migrate to Orchestrate v145

## From

v144

## Observable changes

v145 makes acceptance one commit-backed instrument with independent agent and user evidence.
`acceptance start --task-id <task> [--sha <exact>]` creates the managed detached checkout from the
managed integration branch ref; omission selects its tip and an explicit value must be a full SHA on
its first-parent history. Integration worktree presence, checkout and dirt no longer participate.

`acceptance result` now requires `--verifier agent|user`. Agent pass/fail acts on the existing
`accepted` ref; user pass/fail acts on `user-accepted`. Pass may move either ref backward and reports
the regression. Failure revokes only the same verifier's equal ref. Status, telemetry and reports
project both evidence streams. User evidence does not affect landing or closeability.

Canonical tests and both ReviewGate axes run on the managed acceptance checkout. Integration may
advance without invalidating that snapshot. Mandatory simplify and ticket/Slice verifier prose are
removed; `/simplify` remains an explicit stable-after refactor activity outside acceptance.

## Active-task impact

No ref or task state is migrated. Existing `accepted` remains agent/ReviewGate authority;
`user-accepted` is absent until explicitly recorded. Existing callers must add
`--verifier agent` to their current machine ReviewGate result command. Missing verifier fails with
`cli_usage` rather than guessing.

A user result or user-ref regression requires a current explicit user message. The CLI records the
claim and exact SHA but cannot authenticate conversation origin. Acceptance failure records evidence
and verifier-local ref state only; it creates no repair work.

## Manual steps

1. Stop new acceptance result calls at an installation boundary and read this guide. When upgrading
   from an older installed release, apply every intervening migration guide in order.
2. Update every caller of `acceptance result` to pass `--verifier agent` or `--verifier user`.
3. With separate current setup authority, run normal setup from the primary source checkout.
4. Reload the applicable runtime and run installed doctor plus a disposable acceptance start/result
   exercise for both verifier values.
5. Only with separate pin authority run `pin set`. Setup and pin do not infer landing, cleanup or
   user-validation authority.

## Verification

Run source and installed doctor, `doctor diff 144 145` unfiltered and per runtime, canonical test
discovery, static/compile/shell checks, and disposable real-Git lifecycle tests. Prove explicit old
SHA selection, integration-worktree independence, required verifier, independent pass/fail,
backward ref movement, status/report projection, and cleanup after report capture.

## Rollback

Before setup, reject the source and repair it through the reviewed task branch. After setup, stop
new acceptance mutations and repair forward; do not synthesize or delete either acceptance ref,
rewrite pins, or infer user evidence. Existing exact refs and managed worktrees remain evidence until
an independently authorized cleanup.
