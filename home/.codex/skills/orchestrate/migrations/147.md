# Migrate to Orchestrate v147

## Pi Root Context Epochs

Pi Root may now renew its context at ticket boundaries when the optional
`handoff_context_status` and `handoff_context` tools are available. An epoch is expected to span
roughly one to three tickets, without imposing a limit; related tickets remain together while their
shared context is useful.

Before a transition, Root brings the durable task record to the exact ticket boundary and uses the
read-only status tool as a preflight. An unavailable grant leaves the task's existing `HANDOFF.md`
unchanged. An available grant lets Root overwrite that per-task file with only the clean commit SHA,
durable artifact pointers, next ticket or coherent ticket group, next action, and blockers. The
transition call remains the authoritative authorization check and is the old epoch's final tool
action.

After transition, Root rereads the active skill, frozen spec, admission standard, and complete task
record before repeating Git and runtime checks. Context Epochs do not continue writer sessions or
grant admission, Contract, lane, persistence, or cleanup authority. Codex and Claude runtime
bindings are unchanged.
