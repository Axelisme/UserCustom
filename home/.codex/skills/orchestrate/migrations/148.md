# Migrate to Orchestrate v148

## Rolling writer handoff

A writer dispatch now supplies one stable `Handoff path` for its logical ticket stream. At a
terminal exact clean SHA the lane worker replaces that bounded current-state snapshot through the
fixed sibling `<path>.tmp` and `mv -f`; the old handoff is not retained. A newly admitted correction
lane starts a fresh worker at its own canonical cwd and recovers task context from the same path.
The handoff is advisory and never replaces Root's Git or admission checks.

Acceptance re-review does not use the writer handoff. `acceptance start` recreates the managed
checkout at the same canonical lexical cwd, so after the old reviewer process is terminal Root
resumes each original Standards or Spec reviewer session against the newly bound exact SHA. An
untrusted reviewer context receives a fresh review with the prior terminal report supplied.

## Active-task impact

Existing active writer sessions may finish under their admitted dispatch. Before their next fresh
writer launch, choose one stable absolute handoff path outside disposable managed worktrees and
include it in every lane of that logical ticket stream. The normal durable location is
`<task-record>/artifacts/handoffs/<ticket-id>-worker.md`. Keep exactly one active writer for that
path. Do not migrate or synthesize historical session text into it; its first writer creates the
current snapshot.

Before a re-review resume, confirm the previous reviewer process is terminal, run `acceptance
start`, and bind the recreated checkout's detached, tracked-clean exact subject. A stopped or
untrusted reviewer session follows the documented fresh-review fallback.

## Manual steps

1. Read this guide at the source/install boundary and update Pi Root dispatch prompts to carry the
   stable writer `Handoff path`.
2. With separate current setup authority, run normal setup from the primary source checkout.
3. Reload each runtime and run installed doctor plus a disposable writer handoff and Pi re-review
   exercise.
4. Only with separate pin authority run `pin set`.

## Verification

Run source and installed doctor, `doctor diff 147 148` unfiltered and per runtime, canonical test
discovery, and static/compile checks. In a disposable task, prove that a correction worker at a new
cwd reads the existing handoff, replaces it through the fixed temp path without retaining the old
content, and leaves it unchanged when no exact clean subject exists. Prove separately that
acceptance re-review recreates the same lexical cwd and resumes each reviewer on the new exact SHA.

## Rollback

Before setup, reject the source and repair it through the reviewed task branch. After setup, stop
new dispatches and repair forward. Existing handoff files are task-record artifacts: preserve them
until their normal task cleanup owner removes or archives them; never infer lane, acceptance,
landing, or cleanup authority from their contents.
