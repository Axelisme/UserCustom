# Migrate to Orchestrate v149

## Reviewer-written review reports

A reviewer dispatch now supplies one `Report path` outside the managed acceptance checkout, bound to
that axis and that exact SHA. At its terminal report the reviewer writes the same report there
through the fixed sibling `<Report path>.tmp` and `mv -f`, creating the parent directory when
absent. That path is the reviewer's only authorized write; a blocked review or one that reaches no
terminal report leaves it untouched. The 400-word cap covers the file, which carries the same
report, not a longer one.

Root previously transcribed both axes into a receipt of its own. That step is retired: Root records
the verdict, counts and the two report paths in the receipt it already writes at collection, and the
review evidence stays in the reviewers' own words. A written report is evidence only once Root
accepts it — the axis and exact SHA in the path are what distinguish a superseded review from the
current one, which matters when a reviewer pair is refused and rerun at a new bound SHA.

Reviewers remain read-only against the subject: the acceptance checkout is never modified, and Root
must supply a `Report path` outside it. Dispatching a reviewer without one is `blocked_on_decision`.

## Active-task impact

Reviews already dispatched may finish under their admitted contract and be transcribed as before.
From the next reviewer dispatch, include a `Report path` per axis; the normal durable location is
the task record's artifact directory, and one path is never shared between the two axes.

## Verification

Run source and installed doctor, `doctor diff 148 149` unfiltered and per runtime, canonical test
discovery, and static/compile checks. In a disposable task, prove that each axis writes only its own
path through the temp sibling, that a blocked review leaves the path absent, and that a rerun at a
new exact SHA writes a new path rather than replacing the superseded one.

## Rollback

Before setup, reject the source and repair it through the reviewed task branch. After setup, stop
new reviewer dispatches and repair forward. Written reports are task-record artifacts: preserve them
until their normal task cleanup owner removes or archives them, and never infer acceptance,
landing, or cleanup authority from their contents.
