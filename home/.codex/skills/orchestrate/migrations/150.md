# Migrate to Orchestrate v150

## Every mutation event names the code and the pin that produced it

Each telemetry event now carries two additional fields: `orchestrate_version`, the version of the
code that wrote the line, and `repo_pin`, the repository's pinned version at that moment. A
repository with no pin records `repo_pin: null` rather than omitting the field, because a missing
pin is itself a fact a report needs.

Neither value is computed for the event. The version is the CLI constant and the pin is read once
per process and cached; a pin cannot change inside one process without the pin command, which ends
it.

## A lane span records how the lane ended

A lane span in the report timeline now carries `disposition`, exactly `collected` or `dropped`,
taken from the terminal `integration-collect` or `lane-drop` event that closed it. The report gains
a `lane_durations` object totalling lane time under those two keys separately.

This exists because the two are not comparable. A dropped lane's span is the wall time from its
creation to whatever batch drop eventually cleared it — largely time nobody was working on it. One
observed lane held a 1956-minute span for exactly this reason. Summed with collected lanes, that
figure silently becomes what a reader takes for "how long a lane takes".

## Active-task impact

None to the workflow. Nothing in admission, collection, acceptance or landing changes, and no
command gains or loses authority.

**Existing telemetry is not migrated.** Events written before this version have no
`orchestrate_version`, no `repo_pin` and no span `disposition`, and they remain valid. Any reader
of a telemetry file must tolerate their absence; a report generated over mixed history will show
`lane_durations` totals covering only the spans that carry a disposition.

## Verification

Run source and installed doctor, `doctor diff 149 150` unfiltered and per runtime, canonical test
discovery, and static/compile checks. In a disposable task, create a lane and drop it, then confirm
the report shows that span under `dropped` and leaves the `collected` totals at zero.

## Rollback

Before setup, reject the source and repair it through the reviewed task branch. After setup, repair
forward: the new fields are additive and a reader that ignores them behaves exactly as it did at
v149.
