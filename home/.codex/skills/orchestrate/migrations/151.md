# Migrate to Orchestrate v151

## Orchestrate owns the Immutable declaration parse

`Immutable:` is orchestrate's own private declaration key, not a general Git trailer, and
orchestrate no longer borrows Git's "only the final continuous trailer paragraph counts" rule for
it. `git_ops.py:trailer_values` — which read declarations through
`git show -s --format=%(trailers:only,unfold)` — is deleted outright and replaced with
`git_ops.py:immutable_declarations`, which reads the raw commit message (`%B`) and treats any line
as a declaration, in any paragraph, using the exact same key-match tolerance `trailer_values` had:
the key is matched case-insensitively and the separator is a bare `:` — so `Immutable: x`,
`immutable: x`, `IMMUTABLE: x` and `Immutable:x` (no space) are all recognized declarations, same as
before. The *only* behavioural delta from v150 is which paragraphs are read — every paragraph now,
not just Git's final interpreted trailer block — not which lines within a paragraph count.
Continuation lines within each paragraph retain v150's unfolding behavior.

This exists because a commit made across several `-m` paragraphs — each carrying its own
`Immutable:` line — is a normal way to author a Contract-freezing commit, and Git's own trailer
reader silently drops every paragraph but the last. A commit made with
`git commit -m "s" -m "p1" -m "Immutable: a.py" -m "p2" -m "Immutable: b.py"` previously yielded
only `Immutable: b.py`; `a.py`'s declaration vanished with no error. Downstream, that silent drop
showed up as `lane check` / `integration collect` wrongly refusing a correctly-authored
redeclaration with `lane_not_ready` — the redeclared path looked unprotected-and-changed even
though the author had declared it, just not in the final paragraph.

What a declaration *means* does not change: path normalization (`_normalized_immutable_path`),
protection propagation across a lane's first-parent commit range, and redeclaration semantics are
exactly as they were at v150. Only which *paragraphs* of a commit message are read changes — key
matching within a line is untouched.

## Active-task impact

None to the workflow. Admission, collection, acceptance and landing are unaffected, and no command
gains or loses authority. A lane whose Contract-freezing commit already used a single trailer
paragraph (the common case) parses identically under both the old and new reader. Only lanes whose
commits spread `Immutable:` lines across multiple `-m` paragraphs newly parse correctly instead of
silently losing earlier declarations.

## Verification

Run source and installed doctor, `doctor diff 150 151` unfiltered and per runtime, canonical test
discovery, and static/compile checks. In a disposable task, create a lane, commit a Contract freeze
with `git commit -m <subject> -m "Immutable: <path>" -m <unrelated paragraph> -m "Immutable:
<other-path>"`, then redeclare the first path from an earlier paragraph on a later commit and
confirm `lane check` / `integration collect` both succeed.

## Rollback

Before setup, reject the source and repair it through the reviewed task branch. After setup, repair
forward: reverting `immutable_declarations` to `trailer_values` reintroduces the silent-drop bug
this version fixes, so a rollback should only ever be a stopgap while a forward fix lands.
