# Migrate to Orchestrate v152

## Collection names the ticket and keeps the lane

`integration collect` now requires `--ticket`. The value uses the existing bounded identifier
rule and is written as one `Ticket:` trailer alongside the existing `Task:` and `Lane:` trailers
on the collect commit. A collect without a bounded ticket is a CLI usage failure before any
repository mutation.

Collection is no longer lane cleanup. A successful collect advances integration but retains the
lane worktree, lane branch, and lane base ref. The base ref remains the original base captured by
`lane create`; it is not replaced by the current integration commit. `lane drop` remains the
explicit command for discarding a lane.

## Status is a Git-derived projection

Task status now always has a top-level integer `pending`. Each projected lane has `sha` and
`uncollected`; the latter counts first-parent commits in the lane's original-base-to-tip range
that the current integration tip cannot reach. No durable projection state is written and the
dev-flow ticket store is not consulted.

`pending` counts active lanes that have a recognized collect in the first-parent interval from
accepted to integration, have `uncollected == 0`, and still await agent acceptance. If `accepted`
is absent, the task integration base is the interval lower bound. Untouched lanes do not count,
and the pending count has no ninth-item cap. The ninth-lane warning is independent: it counts
only active lanes with `uncollected > 0`, so collected pending lanes do not trigger that warning.

## Agent acceptance closes clean persistent lanes

An agent pass records its result and advances the accepted ref before attempting closure. Closure
scans only a first-parent forward interval (using the task integration base for the first pass),
recognizes collect commits by their `Task:`/`Lane:`/bounded `Ticket:` identity, and attempts each
unique named lane once. A lane closes only when its tip equals the collect's lane second parent,
`uncollected` is zero, its branch/base/worktree registration matches the managed inventory, and
its worktree is clean in both tracked/index and untracked state. Normal non-force worktree removal
then deletes the lane branch and original base ref.

This is acceptance cleanup, not a rework workflow. New lane work, a newer collect outside the
accepted interval, a missing or mismatched resource, tracked or untracked dirt, an unavailable
collect identity, or a removal failure retains the lane and returns a warning naming that lane.
The acceptance result remains successful and the accepted ref is not rolled back. A retained lane
can be handled explicitly with normal lane operations or `lane drop`.

User verification never attempts lane closure. User pass/fail authority and the existing agent
regression behavior remain unchanged: a regression can warn and move the accepted ref according to
the existing rules, but does not reopen a closed lane or perform reverse-interval closure.

## Active-task compatibility and existing authority

Existing active tasks keep their Git refs, worktrees, acceptance/landing authority, and telemetry.
The normal active-lane guard on `integration remove` remains; an agent pass should close clean
collected lanes before normal task removal, while an explicit lane drop or `--abandon` remains a
destructive operator choice. `integration land` still requires the existing accepted authority and
writes the same landing evidence. Reporting still completes before task cleanup, and telemetry
continues to record collect, acceptance, landing, and removal events until the original cleanup
owner removes the task telemetry.

Collect commits made before v152 lack `Ticket:` and therefore are not recognized by the new
projection/closure scanner. They are historical Git evidence, not a reason to invent pending
state. Do not replay an old collect under the new command; inspect the active lane and use an
explicit lane operation or a new bounded-ticket collect when appropriate.

## Verification

Use the production CLI and real Git resources to verify collect → status → acceptance: the collect
commit has `Ticket:`, lane/worktree/branch/original base remain, status reports `uncollected: 0`
and `pending: 1`, and an agent pass closes the clean lane before normal remove. Also verify that
new work, newer collects, tracked dirt, untracked dirt, resource mismatches, user verification,
and regressions retain or preserve authority with a named warning where required.

Run source and installed doctor, `doctor diff 151 152` unfiltered and for `codex`, `claude`, and
`pi`, the context/lifecycle and Cycle A/B focused suites, the full pytest suite, compile/static
and setup-shell syntax checks, and `git diff --check` before release.

## Rollback

Before setup, reject the v152 source and repair through the reviewed task branch. After setup,
repair forward rather than replaying collects: the pre-v152 implementation does not understand
`--ticket` and its collect path removes lane resources, which can discard work that v152
intentionally retains. Preserve retained lane refs/worktrees and task records while rolling back,
and use the explicit lane cleanup owner only after the lane has been reviewed.
