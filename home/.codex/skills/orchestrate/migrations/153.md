# Migrate to Orchestrate v153

## Persistent lanes own the workstation

Current Orchestrate authority defines a lane as a persistent writer workstation for the task. The
`ticket` owns the admitted Contract and validation mode, and one lane may serve multiple worker
calls and collect/rework cycles. `integration collect --ticket` retains the lane worktree, branch,
and original base ref; agent acceptance records authority before attempting automatic clean-lane
closure. Clean named lanes close, while newer work, dirt, mismatches, unavailable resources, or
removal failures retain the lane and warn. `lane drop` is the explicit destructive operation when a
lane is no longer needed.

Acceptance failure recovery is context-based: an asset resumes the same session; context debt starts
a fresh run in the same lane; an unnecessary lane is dropped. A semantic Contract change requires
admission, but persistent-lane rework does not automatically create a new lane or session. An
additive-only observable correction opens a new ticket and repeats S1.

## Worker handoff removal

The current `SKILL.md`, runtime-neutral dispatch, Pi runtime, and Codex/Claude/Pi `lane-worker`
profiles no longer define a worker `Handoff path`, custody location, one-writer rule, temporary
replacement, `mv -f`, bounded snapshot, or rolling handoff. The worker's lane-ready terminal report
remains normal runtime output; Root verifies public process-terminal and Git evidence at the bound
lane identity.

The historical v148 receipt remains unchanged and continues to document the retired rolling writer
handoff. It is historical evidence, not current authority.

## Preserved mechanisms

The Pi Root Context Epoch and its task-record `HANDOFF.md` seed remain unchanged. Acceptance-reviewer
profiles retain the external `Report path` atomic replacement protocol. Runtime-codex and
runtime-claude remain unchanged and inherit neutral continuation through dispatch. Dev-flow's durable
custody and handoff concepts are unchanged. Status retains v152's Git-derived `uncollected` projection,
top-level independent `pending`, and factual ninth-lane warning semantics.

## Admission cleanup

Admission standard v3 changes only S4 cleanup: after the task record and receipts are refreshed,
verify automatic clean closure from agent acceptance. A retained lane and warning remain an active
current-task finding and require explicit correction or `lane drop` before closeout; there is no
unconditional Root lane drop. The v152 active-lane reminder remains byte-identical.
