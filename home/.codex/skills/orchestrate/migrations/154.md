# Migrate to Orchestrate v154

## `lane check` reports the lane it just measured

`lane check` computed the lane tip, base, and protected-path set and returned an empty payload. It
now returns `{"sha", "base", "protected_paths"}` on success. Failure output is unchanged: exit 1,
the `lane_not_ready` error, and the same diagnostics.

Two dispatch inputs come from that payload instead of from elsewhere. The expected base is the
returned `sha`, not a second `status` call; the dispatch's immutable paths are the returned
`protected_paths`, not a hand-written list. A mistyped protected path has already made one lane
permanently uncollectable, and admission standard S2.6 now forbids hand-rebuilt expected values
generally.

## Collection enforces the predicates it always enforced

The lifecycle no longer instructs Root to run `lane check` before collection, or to rerun it until
it exits 0. `integration collect` applies the same first-parent, cleanliness, topology, and
declaration predicates and refuses before any repository change — it always did, so a lane that
fails `lane check` fails collection identically, with the same diagnostics. Deleting the manual
pre-step changes no outcome.

`lane check` is now documented under observation: it is how Root reads a lane, most usefully to
bind the dispatch envelope. Running it remains available and is never wrong; it is simply not a
gate collection needs run first.

The lifecycle steps renumber from eleven to nine. Old steps 4 and 6 are gone; old 5 is now 4, old 7
is now 5, and 8–11 are now 6–9. The reconcile exception now cites steps 4–5 and 6–7.

## A TDD lane reports twice

A TDD lane stops at the frozen Contract before any production line and again at lane-ready. The
first report names each Contract commit SHA with its exact red command and observed red reason plus
the exact clean SHA and tree; Root proves that state and admits implementation between the two. A
worker never crosses that stop on its own judgement that the Contract looks complete. Direct lanes
are unchanged and still report once.

This writes down what the practice already was — Contract checkpoints and paused production commits
exist in current task records — so a lane already working this way needs no change.

## Continuation dispatch rebinds two fields

A first dispatch binds the full envelope. A continuation into a session that already attested its
cwd, Git root/common-dir, and branch rebinds only the exact HEAD and the scope of that call. Exact
cwd, Git identity, branch, HEAD, and write scope remain hard-bound either way, and an identity
mismatch still fast-fails on the next path-bound operation. Restating an unchanged envelope on
every rework call is where a hand-copied envelope drifts from the lane it describes.

## A stop is a decision request

A `lane-worker` stop now carries the exact SHA and tree it fired at, the evidence that fired it, the
smallest proposed correction down to the paths and the change to each, what must not change with
it, and the condition under which that correction proves insufficient together with what that means
for the remaining rework budget. Current task records already contain corrections in exactly this
shape; the profile now requires it. Whether a correction is preserving or semantic is decided by the
originating axis reviewer, not by the worker proposing it.

## `contract-planner` becomes `contract-reviewer`

`contract-planner` is removed across Codex, Claude, and Pi. Orchestrate had already dropped it from
the bound profile set, so this is not a package removal and there is nothing to acknowledge; the
`Oracle authors an executable Contract` dependency chain it described existed in no other file.

`contract-reviewer` replaces it in the fleet but is deliberately **not** bound. Orchestrate binds
only the profiles it dispatches, and no orchestrate lifecycle step dispatches this one — the
admission standard's S2.7 does. The bound roster stays at `acceptance-reviewer` and `lane-worker`,
and editing `contract-reviewer` is not a package change.

It reviews one frozen Contract read-only at the exact pre-implementation SHA on four axes —
production-entrypoint binding, observability, envelope, and whether the frozen assertions can hold
at once — and owes an applicable correction rather than a complaint. It never writes inside the lane, including to repair what it found: the lane has one
writer, its verdict binds to the SHA it read, and a Contract it edited is one it would then be
reviewing itself.

Admission standard S2.7 says when that review is owed: more than 1000 test lines frozen before the
first production commit. The threshold is provisional and asks to be reported on.

## Pi writer resume rebinds from the check

`runtime-pi.md` no longer pairs `lane check` with a `status` call to recover the lane SHA — the check
reports it. A resume into a session that already attested its cwd, Git root/common-dir, and branch
rebinds only that SHA and the scope of the call; a fresh run in the lane rebinds the full identity.

## Preserved mechanisms

Acceptance, landing, reporting, timing, pin, doctor, release, telemetry, lane persistence, the
ninth-lane warning, and the `lane drop` contract are unchanged. Standards and Spec ReviewGate stay
on the managed acceptance snapshot; nothing moves earlier.
