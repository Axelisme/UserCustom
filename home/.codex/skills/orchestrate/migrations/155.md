# Migrate to Orchestrate v155

## S1–S5 move here from the shared admission standard

`references/admission.md` is the normative S1–S5 authority for dispatched work. It was
`dev-flow/references/admission-standard.md`, which is deleted; dev-flow keeps S0 and now carries it
inline in its own `SKILL.md` rather than in a separate file.

The split is by evidence. S0 admits a design against a need and a usage envelope the user confirmed
and the task record holds — dev-flow's own material, and it applies to work that never creates a
lane. S1–S5 admit a Slice against Git artifacts orchestrate already holds: exact SHAs, first-parent
topology, `Origin: contract` and `Immutable:` trailers, protected paths, acceptance snapshots,
landing tree equality.

`standard_version` is gone. It was hand-maintained, had no doctor and no programmatic consumer, and
a repository could sit pinned at one orchestrate version while reading a standard that had moved on.
These checks now ship in the manifest, are checksummed by `doctor`, and are versioned by
`skill_version`. Historical records citing "Admission Standard v3" or "v4" mean the standard as it
stood at orchestrate v149–v154; cite the orchestrate version from here on.

## The production-diff line limit is removed

S1.3 required an estimated non-test production diff of at most 1500 lines. It thresholded the wrong
variable: across three measured Slices the one with the largest rework had the smallest production
diff, while frozen Contract depth ordered the same three monotonically. S2.7 thresholds that
variable instead. What size was standing in for is carried by S1.3 (independently landable, first
accepted checkpoint days away) and dev-flow's S0 Slicing stage.

S1 renumbers: the old S1.4 is now **S1.3**, and there is no S1.4. A record citing the old S1.3 means
the removed size limit, not independently-landable.

## Restatements collapse

Three checks described mechanisms orchestrate already enforces, in a file that could not see them.
In one file they are visibly redundant and are gone:

- S3's Active lane reminder repeated the ninth-warning semantics `SKILL.md` defines.
- S4's "a passing agent-verifier result records ReviewGate authority" repeated what
  `acceptance result` does and `SKILL.md` step 7 states.
- S5's ancestor, squash, tree-equality and append-only predicates repeated what `integration land`
  enforces before it mutates anything.

S4's closeout list reverses its delegation to match: steps 1 and 2 are dev-flow's contract and step
4 is the repo's, stated where they belong instead of restated here.

## `contract-reviewer` is now bound

v154 shipped `contract-reviewer` unbound because S2.7 lived in dev-flow and no orchestrate step
dispatched it. S2.7 is here now, so orchestrate dispatches it and the manifest binds it. The
dispatched roster is `acceptance-reviewer`, `contract-reviewer`, and `lane-worker`; the manifest's
profile entries go from seven to ten. Editing `contract-reviewer` is a package change from here on.

## Preserved mechanisms

Every CLI surface, exit code, ref, trailer, telemetry field, and lifecycle step is unchanged from
v154. This release moves and deletes text, adds one profile binding, and removes one check.
