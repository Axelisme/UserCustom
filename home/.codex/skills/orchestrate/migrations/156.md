# Migrate to Orchestrate v156

## Removing a document is now possible, and must be declared

`release` refused to publish while any document its current manifest listed had gone missing. That
rule was written for the edit case — publication necessarily rewrites documents the manifest still
hashes — and it made document removal unreachable: deleting a file is exactly what makes it
missing. `compare_manifests` had carried an `acknowledge_removed` channel the whole time with no way
to reach it.

`release --version <exact-next> --drop <path>` (repeatable) declares an intended removal. The
preflight then accepts that path's absence, and rejects a `--drop` that names a path outside the
current manifest or one still present on disk. Removal is declared rather than inferred because an
absent file is the only evidence either way: a deliberate deletion and a lost file are the same
observation.

## Bundled history starts at v141

Manifests `130`–`140` and migration guides `131`–`140` are removed. Nothing was pinned below v141,
and `doctor diff` against a removed manifest now fails rather than silently comparing.

With the floor at v141 the pre-v137 manifest shape is unreachable, so its support is gone: the
legacy profile entry (`bytes`, `sha256`, `standing_orders_sha256`, `profile_contract_sha256`), the
`runtime_assets` category that only v137 and earlier carried, the v136→v137 profile-acknowledgement
special case, and the `profile_standing_orders`/`profile_contract` helpers that fed them. A profile
entry is `agent_name` plus `prompt_sha256`, unconditionally. `runtime_assets` in any manifest is now
rejected outright rather than by version.

## `lane check` reports the Contract commits it walked

`admission.md` asserted that `Origin: contract` distinguishes a Contract commit from an
implementation commit, and leaned on that to make S2.5's first stop and the frozen-depth threshold
derivable from Git. Nothing wrote the trailer on purpose and nothing read it: `commit_trailer_values`
was only ever called with `Task`, `Lane`, and `Ticket`.

Both ends are now connected. `lane-worker` declares `Origin: contract` on every Contract commit and
neither trailer on an implementation commit; `lane check` walks the same first-parent range it
already walked for `Immutable:` paths and adds `contract_commits` to its payload. The frozen-depth
line count is still not computed — the commit set is reported, and `admission.md` says so.

## Direct lanes were being asked for Contract evidence

S2.5's two stops and the S2.8 Contract review read as unconditional, but a direct lane freezes no
Contract commits at all: it has no Contract SHA to prove red at and no frozen test lines to
threshold. S2.5's table now marks its first stop TDD-only, and S2.8 opens on "In a TDD lane". A
direct lane proves its lane-ready state and nothing else.

## S2 gains a check and renumbers

**S2.7 Satisfiable together** — the frozen assertions must be able to hold at once — is new. It was
already being judged: `contract-reviewer` shipped with it as one of its four axes while
`admission.md` defined no such check, so the profile pointed at a file that did not contain the
criterion it was applying. Contract review moves from S2.7 to **S2.8**. A record citing S2.7 under
v155 means Contract review; under v156 it means satisfiability.

## Restatements and leftovers

- `SKILL.md`'s authority list said Root owns "pre-collect test review". v155 deleted that activity;
  the two parallel lists in `dispatch.md` and `runtime-pi.md` were updated and this one was missed.
  It now names the S2.5 mechanical guarantee, like the others.
- `lane-worker` restated Root's validation-mode *selection criteria*, which the worker never acts
  on. It keeps the half it does act on — follow the mode you were given, never downgrade TDD, stop
  if the judgment changes — and points at the lifecycle for the rest.
- `runtime-pi.md`'s authority list opened with "Beyond the shared authority in dispatch.md" and then
  repeated six of the shared items. It now lists only Pi's additions.
- `dispatch.md` used "envelope" for two different things: dev-flow's frozen usage `Envelope`, and
  the five facts a dispatch binds. The second is now the **identity binding**, named once and reused.

## Preserved mechanisms

Every ref, trailer, telemetry field, exit code, and lifecycle step is unchanged. `lane check` gains
a payload key; `release` gains an optional flag.
