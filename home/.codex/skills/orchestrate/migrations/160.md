# Migrate to Orchestrate v160

## The Pi handoff seed is inline

`handoff_context` now receives the complete seed directly. The old sequence wrote that seed into the
task's `HANDOFF.md` and passed the file; step 4 prepares the same six lines and step 5 passes them.

The file was a second store for content that had exactly one reader — the next epoch, once. It was
overwritten between epochs, so a reader arriving mid-window found a seed describing an epoch that had
already ended, and nothing on the page said so. Passing the seed inline removes the window: the seed
exists only in the call that consumes it.

What the seed may contain is unchanged. The three locating commands are still listed rather than
summarized as "run the locating commands", and a SHA, tree, ref name or user quote still must not
appear — the seed is a locator, and those values go stale. Quotes stay in the record's
`Standing orders`, the one place with a retirement mechanism.

The preflight is unchanged in effect and shorter in wording: without an available grant for the exact
session, Root remains in the current epoch. There is no longer a file to leave unchanged.

## A Context Epoch changes a projection, not a context

"A Context Epoch renews Pi Root's context" is now "changes Pi Root's model-context projection". The
authority sentence after it is untouched. Renewal read as though the epoch produced a fresh Root, and
the durable state an epoch carries across is precisely what is not renewed.

## runtime-pi.md stops restating the neutral contract

Four passages were the shared contract written a second time in Pi's words, and each now points at
the file that owns it:

- the writer recovery matrix, which duplicated dispatch.md's worker context routing table
- the identity checks enumerated inside the evidence rule, which duplicated dispatch.md's identity
  binding
- the acceptance re-review paragraph's checkout binding and report rules, which duplicated
  admission.md
- the authority list, which enumerated what SKILL.md and dispatch.md already own

A restatement is a second copy that drifts from the original, and the reader cannot tell which copy
is current. That cost is paid per runtime, so it is worth paying attention to in a runtime binding
before anywhere else: three bindings restating one contract produce three versions of it.

The intro's closing sentence went with them. It named dispatch.md as the owner of the neutral rules
immediately before the file stopped observing that ownership.

## The verified-version sentence is removed

`subagent doctor` still runs read-only at task start, and Root still stops when a required capability
is missing or its behavior does not match this binding. Naming Pi Subagents `0.40.0` as "the last
verified version, not a version pin" invited exactly the version-string comparison the surrounding
paragraph refuses, and the number aged without anything updating it.

## What this costs

The seed is no longer inspectable after the fact. When an epoch transition goes wrong, there is no
file left on disk to read — the evidence is the tool call. That is the same trade the record already
makes for every other transient projection, and the seed was never authoritative for anything.

## Preserved mechanisms

Text only. No CLI grammar, payload key, ref, trailer, exit code, or lifecycle step changes. Codex and
Claude runtime bindings are untouched. A task mid-epoch under v159 needs no action: the next
transition uses the inline form, and an existing `HANDOFF.md` is inert and may be deleted.
