# Migrate to Orchestrate v161

## `lane check` is told the mode and can refuse it

`lane check` accepts `--expect-mode tdd|direct`, and dispatch now runs it that way. Root declares the
ticket's admitted mode; the command answers from Git. A lane admitted TDD that froze no Contract
commit for this ticket, and a lane admitted direct that froze one, both exit 1 with
`validation_mode_mismatch`.

"A worker cannot downgrade TDD to direct" was prose in three files and enforced by nobody. Root was
the only thing standing between an admitted TDD ticket and a lane that quietly skipped its Contract,
and Root judges that by reading the same lane it is about to trust. The rule is unchanged; what
changed is that the check that already runs before every dispatch can now fail on it.

Orchestrate still stores no task narrative. The mode arrives as an argument on the call that needs
it and is never written down here — an orchestrate command that appeared to know the ticket's mode on
its own would be inventing it.

The flag is optional. Omitted, `lane check` behaves exactly as it did in v160.

## The ticket's Contract is not the lane's Contract

Two payload keys are new: `ticket_contract_commits` and `ticket_contract_added_lines`.

A persistent lane keeps its original base across collect cycles, so `contract_commits` accumulates
every Contract the lane ever froze, for every ticket it ever served. Read as "this ticket's
Contract", it is wrong in both directions: it reports a frozen Contract for a ticket that froze
nothing, and it never reports empty for a lane that once did TDD work.

The ticket's Contract is the part integration has not collected — the same first-parent window
`status` already projects as `uncollected`. `ticket_contract_commits` is that subset, and
`--expect-mode` keys off it. `contract_commits` keeps its existing meaning and its existing name.

## S2.8's depth is measured

`ticket_contract_added_lines` is the added lines across those commits. S2.8 previously said "the
commit set is reported, the line count is not yet", leaving its 1000-line threshold to be estimated
by whoever was reading — a threshold whose whole justification is three measured data points
(604/1071/1664) was itself unmeasured at the moment it fired.

A Contract commit carries tests, fixtures and test adapters by construction, so its added lines are
the test lines the threshold counts; no path heuristic decides what a test file is. Binary paths
report no count and contribute nothing.

## Validation mode has one authority

Mode selection, the obligations of each mode, and the no-downgrade rule now live in
[admission](../references/admission.md) S2, beside the `Origin: contract` trailer mechanics that were
already there. SKILL.md's lifecycle step 3 and dispatch.md's restatement become pointers.

The three copies had already begun to differ in what they emphasized, and a reader could not tell
which was current. Admission is where the mode is chosen, so admission is where it is defined.

## dispatch.md stops restating S2.5

Two restatements go. "proven by executing it at the exact bound SHA, not read out of the diffs that
produced it" is S2.5's own sentence, printed immediately after a pointer to S2.5. The direct-mode
evidence list appeared twice inside dispatch.md itself, forty lines apart; the copy in the worker's
terminal report contract is the one that survives.

## S5 says what an unattended run may do

S5 opens by granting rather than only forbidding: S1–S4 are Root's own authority, so a run with no
user present carries a Slice all the way to an accepted snapshot without asking, and S5 is where it
stops. The landing bullets are unchanged.

The prohibition was already there and already derivable. The grant was not, and its absence costs
the opposite failure — a Root that stops to ask at S2 because nothing told it that S2 was its.

## What this costs

`lane check` now runs `git diff --numstat` once per uncollected Contract commit, and one
`rev-list` over the integration branch. On a lane with no frozen Contract that is one extra
`rev-list`.

`--expect-mode` can be wrong. It is Root's declaration, not a fact orchestrate holds, so a Root that
passes the wrong mode gets a confident refusal or a confident pass about a mode nobody admitted. That
is the same trust the dispatch payload already places in Root, and the alternative is orchestrate
storing task narrative.

## Preserved mechanisms

No ref, trailer, exit-code direction, or lifecycle step changes. `contract_commits` keeps its meaning;
the two new keys are additive, and a reader of the v160 payload is unaffected. `lane check` without
`--expect-mode` is byte-identical in behaviour to v160.
