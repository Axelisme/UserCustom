# Migrate to Orchestrate v163

## The lane's declarations are computed, never typed

A worker changed `test_c40_plot_publication_authority.py` and declared
`test_c40_plot-publication-authority.py`. Both are well-formed paths, so nothing rejected it: the
typo entered history, the collect predicate saw a protected path changed without a covering
declaration, and because that predicate re-walks the whole first-parent range on every call, the
verdict was permanent. The lane was mechanically uncollectable from that commit onward.

Admission S2.6 already forbade this — "a digest, identity, byte count, payload **or protected path**
… produced by the production code or by a script that computes it, never rebuilt by hand." Protected
paths were the one item on that list with no script behind them. v163 supplies it.

```
lane commit --task-id <task> --lane-id <lane> --message-file <file> [--contract | --amend-frozen]
```

| mode | declares | `Origin:` |
| --- | --- | --- |
| no flag | nothing, and **refuses** when the staged set touches a frozen path | — |
| `--amend-frozen` | the staged paths that are already protected | none |
| `--contract` | every staged path | `contract` |

The declaration set comes from `git diff --cached` against the lane tip, which is the same set the
collect predicate compares against, so the two cannot disagree. `--message-file` rather than `-m`
keeps quoting and multi-paragraph messages out of the worker's shell.

**A merge in progress is a supported input, not an error.** After `merge --no-ff --no-commit` the
commit Git writes has two parents with the lane tip first, and the staged diff against that tip is
exactly what the predicate will later read.

### Why the unflagged mode refuses instead of declaring for you

This is the one line most likely to be "optimised" away later. If the tool declared every frozen path
it found staged, every commit touching a frozen test would be stamped automatically and collect would
never refuse again — the mechanism would still be running and would no longer mean anything. The
value of `Immutable:` is not that the path is written down (`git show --name-only` shows that); it is
that touching frozen work is an explicit, deliberate act.

The refusal keeps the act explicit while removing the hazard that caused the failure: the worker
types a fixed flag, not a filename. A wrong flag fails loudly at argparse; a wrong filename fails
silently, in history, forever.

## `lane sync` stages the merge and stops

`lane sync` no longer commits. It leaves the merge staged and hands the lane back.

The reason is a merge Git resolves cleanly that is nevertheless wrong. Under the old behaviour sync
committed it immediately, producing a lane tip nobody had tested that `lane check` would report
ready; the error surfaced a round later, at Root's S2.5 gate, paid for by the wrong agent. A staged
merge is dirt, so `lane check` refuses until the writer commits — the detection moves to the only
agent who can fix it cheaply, and cannot be skipped.

The writer signs the merge with `lane commit --amend-frozen`, which computes the same redeclaration
set sync used to compute inline. That code is now in one place instead of two.

**Conflicts are no longer an error path.** `merge_conflict` is retired from `lane sync`: a conflict
exits 0 with a warning naming the conflicted paths, and records telemetry outcome `conflict`. The
merge ran exactly as asked and the result needs the writer — that is the handoff working, and exit 1
is reserved for a completed negative predicate. **A caller that treats a non-zero `lane sync` exit as
"sync failed" will now see success where it used to see failure.** `integration collect` and
`integration reconcile` keep `merge_conflict` unchanged.

The `lane-sync` `success` outcome also changes meaning, from "the merge is committed" to "the merge
is staged". Reports and telemetry readers see that shift; `sync_conflicts` in the report counts a
real event for the first time.

## The worker profile gets the item it was missing

`references/admission.md` listed protected paths in S2.6. All three `lane-worker` profiles restated
that sentence with `protected path` dropped — so the only agent that actually types those strings
read the version with its own case deleted. The item is restored in all three, and the profiles now
carry a branch-free recipe: every commit in the lane goes through `lane commit`, with the flag
selecting the mode. `admission.md` itself needed no change; it was already correct.

## What this costs

Workers gain a required tool call where `git commit` used to be enough, and a lane whose sync Root
ran is left dirty until the worker returns to it — deliberately, but it is a state the old flow did
not produce. The class is reduced, not eliminated: orchestrate does not own the worker's shell, so a
worker can still run `git commit` by hand and declare a path that does not exist. Adoption is the
whole of this instrument's force, which is why there is one verb covering every lane commit rather
than two special-purpose ones.

`lane check` still does not warn about a declaration for a path the commit never touched. Such a
declaration is inert — a path nobody changed never enters the predicate — so it costs a lane nothing;
it is left unbuilt rather than deferred silently.

## Preserved mechanisms

The collect predicate, the `Immutable:` reader (case-insensitive key, bare `:`, per-paragraph scan,
continuation unfolding), append-only integration provenance, the fixed-parent collect commit, S2.8's
depth measurement, and every other command's grammar and exit codes are unchanged. A Contract
amendment still carries no `Origin: contract`: that trailer marks a freeze, and S2.8 measures depth
over Contract commits frozen before the first production commit, which an amendment is not.
