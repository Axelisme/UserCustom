# Migrate to Orchestrate v164

v163 shipped `lane commit` and left one end loose. This is that end, plus two documentation
corrections found in the same audit.

## The ledger can read the events the new verb writes

`lane_commit` records a `lane-commit` telemetry event, and `_EVENT_OPERATIONS` did not list it. Every
event outside that allowlist is counted invalid by `_decode_events`, so `report` answered with
`invalid_telemetry_lines` and an `ignored N invalid telemetry line(s)` warning — **N growing with the
number of commits the worker made correctly.** v163 made that verb mandatory for every commit in a
lane, so the noise scaled with adoption of the thing v163 exists to encourage.

`lane-commit` is now in the allowlist. It gets no projection in `compute_report`: no count, no
timeline marker. The event is in the ledger and readable, and the commit itself is in Git with its
`Task:` and `Lane:` trailers, which is where anyone asking what a lane contains should look. A
per-commit marker would bury the lifecycle markers the timeline exists to show.

The regression survived v163's suite because no test ran `report` after `lane commit`. One does now,
and it asserts the count rather than the absence of a string — the allowlist can only be forgotten
again by making that assertion fail.

## S2.4's list had five items in the profile and four in the standard

`admission.md` S2.4 names what a preserving test correction must preserve: **observable behavior,
public Interface, envelope and acceptance surface.** All three `lane-worker` profiles restated it as
"the admitted observable, *expected behavior*, public Interface, usage envelope, and acceptance
surface" — one item more than the standard has. It entered in v132 and has been the version the
worker actually reads ever since.

The extra item is removed. `admission.md` is unchanged: it was right.

This is the same defect class v163 fixed in S2.6, in the neighbouring paragraph, and it is worth
naming plainly: **these profiles restate admission policy, and `admission.md` itself says they should
not.** The restatement stays anyway, because the profile is a standalone prompt with no route to
`admission.md` — replacing the rule with a pointer would delete it from the only context that acts on
it. Closing the class needs the worker to be able to read the standard, which is a change to who may
read the skill and is not attempted here.

## One sentence that did not parse

`SKILL.md`'s `lane check` paragraph ended:

> This is how Root reads a lane — most usefully to bind the identity binding a dispatch carries —
> not a gate collection needs run first

which is not a sentence. It now reads:

> Root reads a lane this way most usefully before dispatch, to bind the identity binding it carries.
> It is not a gate collection requires running first — a lane that fails it fails collection
> identically, with the same diagnostics.

## What this costs

A release for one allowlist entry and two sentences. The alternative was leaving a report artifact
that miscounts its own ledger, which is worse: the number is not merely noisy, it is the number a
reader would use to decide whether the telemetry is trustworthy at all.

## Preserved mechanisms

No CLI grammar, payload key, exit code, error code, ref, trailer, or lifecycle step changes.
`lane commit` and `lane sync` behave exactly as v163 shipped them. The report's `counts`, `rates`,
`timeline`, and `authorities` keys are unchanged; `invalid_telemetry_lines` now reports zero for a
lane that used the instrument, which is what it always should have reported.
