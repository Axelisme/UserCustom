# Migrate to Orchestrate v165

Everything here serves one measurement: an agent re-orienting after a handoff read **36,698 bytes**
of skill — dev-flow's `SKILL.md` (14,134), this one (9,965), and `admission.md` (12,599) — whatever
it had come back to do.

## Two readers, not three situations

Post-compaction re-orientation, a new session picking up an existing task, and a first use of the
skill look like three cases. They are two:

| | knows the mechanism | knows its position |
| --- | --- | --- |
| re-orienting, or a new session on an existing task | no | **yes** — `locate` and `status` answer cheaply |
| first use | no | no, and it does not know those commands exist |

`runtime-pi.md` told the first reader to "reread the active skill, frozen spec and admission". That
instruction is written for the second reader, and the first paid its price every time — even though
the seed's three commands run *before* it, so the position was already known when the reread began.

## What changed

**`admission.md`'s S2.1–S2.8 are headings.** They were bullets inside a 5,808-byte `## S2`, so any
"see S2.5" cost the whole section. S2.5 is 1,003 bytes; S2.4 is 547. A Root about to collect needs
those two and nothing else.

**Every lifecycle step names the section that governs it.** Only step 3 did. Steps 5–9 and the
rework path did not, so "read only what you need" was not actionable — the reader could not know
which section to open without opening all of them.

**`lane sync`'s runtime binding reads by position.** The post-transition instruction now lets the
three commands place the reader on one line and opens only what that line points at. Two details are
load-bearing: it falls back to the lifecycle list alone when the commands place the reader *between*
steps, and it re-reads further when what it opens contradicts what the commands reported. Without
the second, a position-aware read becomes a trap the moment the record is wrong.

**The exit-code contract moved to the top.** It sat under `## Package administration`, which is not
where a reader looking for "how do I read this command's answer" would find it, and it is the one
fact every reader needs — including the first-time one.

**dev-flow disclosed three sections.** `S0`, `Keeping INDEX.md small` and `Conditional route` moved
to `references/`, and its post-compaction instruction moved from the last line of the file to the
first section. `Custody` stayed inline deliberately: it governs *reading* a standing order and
acting on it, which happens at every re-orientation, not only when one is written. Behind a pointer
it would be skipped by exactly the reader who most needs it.

**Two reviewer profiles stopped pointing at a whole file.** `acceptance-reviewer` carries S3's
blocker enum inline rather than sending a reader to 12,599 bytes for four values;
`contract-reviewer` points at S2.8 rather than at `admission.md` entire.

## `doctor` now sizes the spine

```json
"spine": {"SKILL.md": 11163, "runtime-codex.md": 432, "runtime-claude.md": 435, "runtime-pi.md": 8380}
```

Only the documents every reader loads. Everything under `references/` is reached from one position
and free at every other, so it is not the standing cost.

**Reported, never refused, and with no threshold of its own.** `verify_release` already refuses any
single manifest document over 16 KB, and keeps doing so. That guard bounds one file; this number is
the sum a reader pays before it has done anything, which no single-file check can see — `SKILL.md`
and `runtime-pi.md` are each comfortably legal while together costing 19,543 bytes at every
re-orientation. Giving the sum a threshold too would reward the one failure this whole change must
not cause: summarising away custody or reasoning to make a budget. `refresh` already takes exactly
this shape for the record.

## Two corrections carried in from the v164 audit

**S2.5's table lived in two files and had already drifted.** `admission.md` says the focused command
is "red, **red for** the named missing behavior" — it is red, *and* red for the right reason.
`gate.md`'s copy said "red, for", losing the distinction the worker profile calls
red-for-the-right-reason. And `admission.md` claimed "only the exit-code direction below is this
standard's" while showing a table with no exit-code column; the column lived only in `gate.md`. The
exit-code column is now in `admission.md`, making that sentence true, and `gate.md` points at it.

**`package-admin.md` described `doctor --path <repo>` as adding "the cwd-derived repository pin
projection".** `--path`'s whole job is to override cwd, and the projection is always attempted.

## What this costs

**This skill's `SKILL.md` grew**, 9,965 → 11,163. It was already lean and its references were
already disclosed correctly; the pointers and the orienting section are new text. The trade is that
`admission.md` leaves the mandatory read: a re-orientation goes from 36,698 to roughly 19,600, and a
Root that is landing reads S5's 778 bytes instead of 12,599.

Every new boundary is a place two files can disagree. The S2 headings do not add one — the content
did not move — but `gate.md`'s pointer to S2.5 and dev-flow's three new reference files do.

## Preserved mechanisms

No CLI verb, flag, exit code, payload key beyond the added `spine`, ref, trailer, or predicate
changed. Every S1–S5 check keeps its substance; S2 gained headings and S2.5 gained a column, and
nothing was removed from the standard. `plan.py`'s `create | archive | locate | refresh` Interface
and its validation are untouched. The ninth-lane warning's counting rule left `SKILL.md` because the
warning is factual, explains itself when it fires, and never blocks creation — the behaviour is
unchanged.
