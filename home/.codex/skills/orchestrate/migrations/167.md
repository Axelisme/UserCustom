# Migrate to Orchestrate v167

## Purpose

Point the lane worker at the `grove` skill for symbol and structure navigation, without changing
the lifecycle, admission, authority, commands, pointers, exceptions, or completion criteria.

## Observable changes

- The lane-worker profiles name `grove` in the same reach-for sentence that already names
  `codebase-design` and `diagnosing-bugs`: reach for it when locating a named symbol or its call
  sites beats grepping for it.
- The Claude and Pi lane-worker profiles add `grove` to their skills declaration; the Codex profile
  carries no such field and changes prose only.
- No validation mode, stop condition, commit rule, identity attestation, or report shape changes.

## Active-task impact

None. Existing task refs, lanes, worktrees, trailers, acceptance state, and records remain valid.

## Manual steps

None required. The recommendation is conditional on the tool being present: without the `grove`
binary the worker proceeds with shell tools exactly as it did at v166, and the `grove` skill itself
carries the install path. A language whose grammar is missing makes grove report zero symbols and
exit 0, so a worker that finds nothing should confirm the grammar with `grove languages` before
concluding a symbol is absent.

## Verification

Run `orchestrate.py doctor` and the repository test suite. Compare the v166 and v167 lane-worker
prompts to confirm the reach-for sentence is the only body change.

## Rollback

Restore the v166 documents and manifest together. Do not pair a v166 manifest with v167 documents.
