# Migrate to Orchestrate v170

## Purpose

Make the package's published section identities directly readable. A reader can now resolve one
manifest address without opening the whole document, and the nine lifecycle steps have their own
addresses beneath the existing parent section.

## Observable changes

- `orchestrate.py show <file>#<section>` writes only the exact released section to stdout.
- The command accepts exact manifest paths and section names, including duplicate-heading suffixes
  such as `[2]`. Unknown sections name the addresses available in that document.
- Before emitting, `show` recomputes the live section's released normalized hash. Drift refuses with
  `section_integrity_mismatch` and emits no document bytes.
- `SKILL.md#Minimum complete lifecycle` remains valid; `SKILL.md#Step 1 — Create integration`
  through `SKILL.md#Step 9 — Remove task` now resolve each step independently.
- Migration guides 141–154 leave the package. Supported bundled manifests already begin at v155.

## Active-task impact

Existing task refs, lanes, worktrees, trailers, acceptance state and records remain valid. Exact
addresses published by v169 remain valid except for documents explicitly removed in this release.
Readers may adopt `show` immediately; no status or dispatch output changes in v170.

## Manual steps

None. `show` reads the executing package's current manifest and requires no repository pin.

## Verification

Run `orchestrate.py doctor`, then resolve both a parent and a child lifecycle address. Confirm an
unknown section exits 2 and names the document's available addresses, and that changing a copied
package section after sealing its manifest produces `section_integrity_mismatch` with empty stdout.

## Rollback

Restore the v169 documents, migration guides 141–154 and manifest together. Do not pair a v169
manifest with v170 package bytes.
