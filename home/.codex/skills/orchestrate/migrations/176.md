# Migrate to Orchestrate v176

## Purpose

Exclude already-integrated production carried by a second lane's sync merge without changing the
Git-derived collect-round field, and keep worker terminal reports from repeating Contract SHAs that
Root can read from `lane check`.

## Observable changes

- `status --task-id <task>` continues to emit the same `collect_rounds` mapping and field name. A
  sync merge is excluded when its second parent is already in the collected integration history and
  its resulting tree is identical to that already-reachable integration commit. Production content
  introduced by a lane still counts, including ordinary production commits and merges whose tree
  adds content beyond integration.
- TDD workers still report the exact red command and observed red reason at the Contract stop, and
  validation commands/results plus worker identity attestation at lane-ready. They no longer repeat
  Contract commit SHAs in terminal prose; Root reads SHA, tree, base, protected paths, and Contract
  commits from `lane check`.

## Report-version decision

`report_version` remains 2. This release changes Git-derived collect-round classification and the
worker dispatch wording, not the report object schema or its wall-clock measurement contract.

## Active-task impact

No report consumer migration is required. Root should continue using the unchanged
`status.collect_rounds` field for measured production-bearing rounds and `lane check` for Contract
and other lane Git facts.

## Manual steps

None.

## Verification

Run the focused machine-facts Contract tests, the canonical test suite, `orchestrate.py doctor`,
and `orchestrate.py doctor diff 175 176`. Confirm the seven focused tests pass, cross-lane sync
carriage remains excluded, and ordinary production counts remain unchanged.

## Rollback

Restore the v175 package and manifest together. The v175 report schema remains compatible; only the
v176 cross-lane collect-round boundary and worker dispatch wording are reverted.
