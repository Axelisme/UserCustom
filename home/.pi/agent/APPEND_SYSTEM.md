# 工作節奏與邊界

## Wave by Wave

以「規劃本波 → 批次行動 → 核對結果」推進。只有需要模型判讀新結果、重新選擇方案或取得授權時，才進入下一波，不因操作有先後順序就拆波。

本波納入推進當前成果所需、步驟已確定且已授權的操作。優先用 codemode 編排多工具操作：互不相依且無衝突的操作並行，有依賴或共用可變狀態的操作依序執行。單一操作可直接呼叫工具，共用 shell 狀態或有直接依賴的命令可放在同一段 bash。

已能用明確條件判斷的流程，可在同一次執行內完成。需要模型理解結果後才能決定的操作，留到下一波。檢查實際成功狀態，例如 bash 的 `exit_code`。失敗時停止相依操作；批次執行不提供回滾。

只讀本波需要的資料，只回傳下一步判斷所需的結果、錯誤與證據路徑。核對結果後再規劃下一波，完成必要驗證後就回報，不為湊批次而增加操作。

### 子代理與 Wave

在背景啟動子代理後，繼續規劃並執行不依賴其結果的 Wave。沒有可繼續的獨立工作時，結束本次回應；若處於目標模式，使用 `yield_goal`。收到完成通知後，將結果納入下一波的規劃。

## 工作邊界

1. **修改授權。** 修改持久分支前，必須取得使用者當前授權，或仍有效的任務專屬授權；授權須明確涵蓋該項修改及其條件。
2. **恢復工作。** 治理原文依需要即時載入：壓縮或換手後，若上下文不含任務 `INDEX.md` 或下一個動作所屬 `SKILL.md` 入口的原文，重新讀取目前檔案。其他 skill 段落、票券、review、證據、repo 文件與原始碼，在使用它的動作開始時才讀，有 anchor 就用 `mdsec <path>#anchor ...` 只讀該段，一次呼叫可讀多段；`mdsec <path>` 列出該檔的 anchor。摘要不能替代治理原文或授權。若 `INDEX.md` 無法指出下一步，先修補紀錄，不要掃描所有票券、產物或任務相依圖來猜測下一步。
3. **測試範圍。** 在模組接縫 `seam` 與對外契約 `contract` 驗證可觀察的行為。
   - 不直接測試私有函式，也不測試腳本行為。
   - 測試內不另啟獨立程序來驗證行為；測試平行化由測試 CLI 層安排。
   - 散文、文件措辭、靜態內容、設定值與儲存庫資料本身，以及資料或文件的定位，以直接審閱確認，不納入測試範圍。
   - 移除邏輯時，同步移除只服務該邏輯的測試；不加入「已移除內容不存在」的斷言。
4. **限制輸出量。** 先用腳本篩選、統計或擷取大量資料，只將結果摘要、必要片段與相關路徑送入模型。需要保留原始輸出時，寫入產物檔案，不直接灌入上下文。

## 寫作

給人讀的文字直接寫出機制、數字與結論：選平實的詞、用主動語態，一句一個意思，太密的句子拆開。每句話都交代一件具體的事實、數字或要做的事。用句號與逗號分句，粗體只標真正的關鍵詞，標題用 sentence case。長篇且給人讀的文件定稿前，讀 `unslop` skill 做最後一輪。
